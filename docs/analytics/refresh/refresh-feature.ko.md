# 설정 문서 최신화: 프런트엔드 동작

이 문서는 현재 프런트엔드가 설정 문서 최신화 과정에서 보여주고, 요청하고, 관찰하는 동작을 설명한다. 체크아웃된 코드를 기준으로 하며 운영 배포본을 검증한 결과나 새로운 애널리틱스 이벤트 계약은 아니다. 코드에서는 이 흐름을 graph refresh라고 부른다.

## 사용자 흐름

1. **확인창 열기.** 작업공간 사이드바의 ‘설정 문서 최신화’를 누르면 확인창이 열린다. 취소하면 최신화를 시작하지 않고 창만 닫는다. 상태를 불러오는 중이거나 API를 사용할 수 없으면 사이드바에 그 상태를 표시한다.
2. **시작하기.** ‘최신화 시작’을 누르면 확인창을 닫고 먼저 열린 문서 저장을 시도한다. 저장에 실패하면 오류를 보여주고 최신화 요청은 보내지 않는다. 저장 후 `POST /projects/{projectId}/graph-refresh`를 본문 없이 보낸다. 대상 문서는 서버가 선택하며 프런트엔드는 문서 목록을 보내지 않는다.
3. **시작 응답 처리.** 응답에 `GENERATING` 실행이 있으면 반환된 파일 목록을 이용해 잠긴 문서 수를 표시하고 진행 중 상태를 보여준다. 실행이 없으면 ‘최신화할 변경이 없어요’라고 표시한다. 요청에 실패하면 시작 오류를 보여주고 현재 상태를 다시 불러온다. 시작 응답이 성공했다고 결과까지 준비된 것은 아니다.
4. **결과 기다리기.** 최근 실행이 `RUNNING`이면 5초마다 상태를 조회하며, 백그라운드 탭에서는 폴링을 쉰다. `RUNNING`은 서버의 `GENERATING`에 대응하는 프런트엔드 상태다. 사이드바에는 진행 표시와 계산 가능한 경우 경과 분을 보여준다. 이 브라우저가 `RUNNING`에서 `READY`, `NO_CHANGE`, `FAILED`로 바뀌는 것을 관찰하면 잠금 정보를 갱신하고 각각에 맞는 알림을 띄운다. 작업공간을 열었을 때 이미 끝난 실행에는 이 전환 알림을 띄우지 않는다. 다른 탭이나 기기에서 시작한 실행도 관찰할 수 있다.
5. **검토하기.** `READY`이면 사이드바에 ‘변경 사항 반영’이 표시되며, 결과 알림에서도 검토창을 열 수 있다. 검토창은 현재 작업본과 제안 작업본을 비교한다. 사용자는 양쪽을 편집하고 내용을 선택할 수 있으며 변경 사항은 자동 저장된다. 모든 작업본의 양쪽이 일치해야 ‘반영 확정’을 누를 수 있다. 현재 내용을 유지할 수도 있으므로 확정이 모든 제안의 수용을 뜻하지는 않는다.
6. **반영 확정.** 프런트엔드는 확정 요청 전에 저장 대기 중인 작업본 변경을 저장한다. 성공 응답을 받으면 검토창을 닫고 성공 알림을 표시하며 관련 상태와 내용을 다시 불러온다. 네트워크 오류 등으로 결과가 불확실하면 무작정 확정 요청을 다시 보내지 않고 실행 상태를 확인한다. 검증·인증 등의 실패는 검토 흐름에서 각각 처리한다.

## 프런트엔드에서 보는 상태

| 상태 | 프런트엔드에서의 의미 |
| --- | --- |
| `IDLE` | 프로젝트의 최신화 실행을 찾지 못했다. |
| `RUNNING` | 결과를 기다리는 중이다. 서버의 `GENERATING`에 대응한다. |
| `READY` | 검토할 결과가 준비됐다. |
| `NO_CHANGE` | 실행이 끝났지만 반영할 변경이 없다. |
| `FAILED` | 실행에 실패했다. 오류 코드가 제공될 수 있다. |
| `APPLIED` | 결과가 확정되어 반영됐다. |

시작 응답에 실행이 없는 경우와 이후의 `NO_CHANGE` 상태는 다르다. 전자는 시작할 변경이 없다는 표시이고, 후자는 실행이 일어난 뒤 관찰한 결과다.
