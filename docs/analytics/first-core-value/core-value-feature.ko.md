# 첫 핵심 가치 도달: 프런트엔드 동작

이 문서는 체크아웃된 프런트엔드의 온보딩부터 설정 문서 최신화까지의 흐름을 설명한다. 운영 배포본을 검증하거나 사용자의 생애 최초 행동을 식별하거나 새로운 이벤트를 정의하지 않는다. 제안하는 흐름 측정은 [핵심 가치 이벤트](core-value-events.ko.md)를 참고한다.

## 사용자 흐름

1. **온보딩 완료.** 조건에 맞는 신규 사용자는 온보딩을 완료하고 예시 프로젝트, 새 프로젝트 또는 나중에 시작을 고른다. 온보딩 완료는 예시 프로젝트 생성보다 먼저 저장된다. 나중에 시작을 선택하면 프로젝트를 만들지 않고 목록으로 갈 수 있다.
2. **프로젝트 생성.** 예시를 선택하면 예시 프로젝트 생성 요청을 보내고 성공 시 작업공간을 연다. 일반 프로젝트는 제목과 선택적인 설명을 입력하면 프런트엔드가 생성 서비스를 호출하고 성공 응답을 처리한다. 프로젝트 생성과 온보딩 완료는 각각 성공하거나 실패할 수 있다.
3. **준비와 최신화 시작.** 작업공간에서 최신화 확인창을 열고 시작한다. 프런트엔드는 먼저 열린 문서를 저장한다. 저장에 실패하면 시작 요청을 보내지 않는다. 시작 성공 응답에는 실행이 있을 수도 있고 최신화할 변경이 없다는 결과가 올 수도 있다.
4. **관찰과 검토.** 실행이 진행 중이면 프런트엔드가 상태를 주기적으로 조회한다. 브라우저가 준비 상태로의 전환을 관찰하면 알림을 표시한다. 진입 시 이미 완료된 실행은 그 전환을 발생시키지 않는다. 준비되면 사용자가 제안을 열어 검토할 수 있다.
5. **반영.** 프런트엔드는 저장 대기 중인 작업본 변경을 저장한 뒤 반영을 확정한다. 성공 응답 또는 응답이 불확실할 때의 상태 재확인으로 반영을 확인할 수 있다. 확정은 모든 제안의 수락을 뜻하지 않는다.

브라우저가 연결을 잃거나 닫히거나 상태 전환을 놓칠 수 있다. 사용자 흐름에서 최신화한 프로젝트가 처음 생성한 프로젝트와 같을 필요는 없다. 프런트엔드 이벤트는 단계 간 동일 프로젝트나 생애 최초 도달을 식별하지 않는다. 최신화 상태와 API 세부사항은 [최신화 프런트엔드 동작](../refresh/refresh-feature.ko.md)을 참고한다.
