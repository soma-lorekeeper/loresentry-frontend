# GA 보고서 게시 결과

[English](ga-report-results.md)

2026-11-03 ego lite를 사용해 GA 속성 **soma**(`557572950`, 계정 `410899988`)의 **보고서 → LoreSentry**에 상세 보고서 네 개를 게시했다. 앞서 진행한 [계측·맞춤 정의 작업](implementation-results.ko.md)의 후속 작업이다. 애플리케이션 배포와 새 운영 이벤트 수신은 아직 검증하지 않았다.

## 보고서 읽는 방법

네 보고서 모두 이벤트 수·총 사용자·활성 사용자당 이벤트 수와 선·막대 차트를 제공한다. 제품 사용 및 설정 오류 탐지 이벤트 보고서의 기본 분류는 이벤트 이름이다. 측정기준 선택기에서 등록된 Usage 분류를 고를 수 있다. 서로 다른 이벤트를 해석할 때 outcome·action은 이벤트 이름을 함께 두고 본다.

제품 계열 정규식은 현재 목록의 **실제 연결된 이벤트명 55개**와 필터에 맞는 기존 이벤트를 포함한다. 기존 이벤트에는 `workspace_entered`·`onboarding_start_selected`·`refresh_review_opened`가 있다. 조건부이며 실제 호출부가 없는 `action_result_resolved` 도우미는 제외한다. 신규 이벤트만 확인하는 배포 감시 보고서는 아니다.

실행 결과 보고서는 **Usage Outcome**(`done`·`failed`·`cancelled`)을 기본 분류로 사용하고, **Usage Processing Seconds**와 **Usage Finding Count**를 추가했다. 유효하게 보고된 값의 합계이며, 없는 값은 제외하므로 모든 이벤트 수로 나눠 평균을 구할 수 없다. 앞서 RUNNING을 본 브라우저만 종료를 관찰하므로 서버 작업 성공률이 아니다. 시작 접수·취소 접수·과거 결과 조회·판정 행동은 더 넓은 설정 오류 탐지 이벤트 보고서에서 별도로 구분한다.

채팅 응답 결과 보고서는 **Usage Outcome**을 기본 분류로 사용하고, **Usage First Content Seconds**와 **Usage Citation Count**를 추가했다. 이 역시 값이 존재할 때의 합계다. 창 열기·요청 시작·기타 채팅 행동에서 `chat_turn_result`만 분리한다.

## 검증과 남은 작업

저장한 컬렉션을 라이브러리에서 다시 열어 모든 사용자에게 게시된 상태를 확인했다. 실제 왼쪽 메뉴에서 두 새 주제를 펼치고 보고서 네 개를 모두 열었다. 저장된 필터·기본 측정기준·측정항목 헤더를 대조했다. 실제 보고서 URL과 목록은 [ga-reports.json](ga-reports.json)에 있다.

화면의 지난 28일 구간(2026-10-06~2026-11-02)에서 제품 사용 보고서에는 필터에 맞는 기존 이벤트가 표시됐고, 새 설정 오류 탐지·채팅 결과 보고서에는 사용 가능한 데이터가 없었다. 보고서 설정을 검증한 것이며, 새로 구현한 이벤트의 수신을 검증한 것은 아니다. 계측을 배포하고 실제 운영 수신을 확인한 뒤 새 보고서를 해석해야 한다. 운영에 가상 이벤트를 전송하지 않았다.
