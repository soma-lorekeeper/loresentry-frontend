# 추가 이벤트 목록

[English](additional-events.md) · [폴더 안내](README.ko.md)

상태: 제안만 작성했다. 이 폴더의 새 이벤트명은 이 문서에서만 정의한다. 기존 이벤트는 [현재 계약](current-state.ko.md)을 유지한다. P0·P1·P2는 적용 묶음이며 배포 상태가 아니다.

## 공통 계약

모든 새 이벤트에 `schema_version: usage_v1`, `ui_locale: ko | en`을 넣는다. 이벤트별로 명시된 파라미터와 아래 공통 필드 중 해당하는 것만 보낸다. 누락은 모름·해당 없음이며, 이를 0·빈 문자열·추정한 성공으로 채우지 않는다.

| 필드               | 허용 값 또는 출처                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| ------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `entry_point`      | `landing_header`, `landing_body`, `landing_footer`, `project_list`, `onboarding`, `sidebar`, `new_tab`, `file_menu`, `document_header`, `editor`, `search`, `graph`, `timeline`, `memo_panel`, `chat_launcher`, `chat_home`, `chat_conversation`, `selection_toolbar`, `check_home`, `check_report`, `check_toast`, `refresh_sidebar`, `refresh_review`, `account_menu`, `guide`, `shortcut`, `other` 중 하나. 실제 호출자를 사용하며 나중 렌더링에서 추정하지 않는다. |
| `document_type`    | `manuscript`, `character`, `place`, `organization`, `item`, `event`, `worldview`. 모르거나 문서가 아니면 생략한다.                                                                                                                                                                                                                                                                                                                                                     |

| `error_category`   | `network`, `auth`, `validation`, `conflict`, `locked`, `not_found`, `unavailable`, `limit`, `cancelled`, `other`. 해당하는 비성공 결과에만 넣으며, 원문·HTTP 본문이 아닌 신뢰할 수 있는 타입화된 상태에서 구한다.                                                                                                                                                                                                                                                      |

| `duration_seconds` | 대응하는 로컬 시작부터 관찰 결과까지의 유한한 음이 아닌 브라우저 경과 초. 이후 캐시 무효화 시간은 제외한다. 단조 시계를 쓰며, 대응 시작을 관찰하지 못했으면 생략한다.                                                                                                                                                                                                                                                                                                  |
| `count_bucket`     | `0`, `1`, `2_5`, `6_20`, `21_plus`. 아래에 별도로 명시한 숫자 개수는 음이 아닌 정수다.                                                                                                                                                                                                                                                                                                                                                                                 |

프로젝트·문서·실행·어긋남·대화·메시지·사용자·시도 식별자는 해시를 포함해 전송하지 않는다. 식별자는 중복 방지와 대응을 위해 **로컬에서만** 사용할 수 있다. 사용자 지정 파라미터로 내용, 제목, 파일명, 검색어, 인용, 이유, 이메일, URL, 오류 원문을 보내지 않는다. 기존 URL·리퍼러 정제를 유지한다.

### 동작 과정

`*_started` / `*_result` 쌍은 유효한 명시적 동작이 담당 조정 코드에 진입할 때, 사전 저장·변경 요청 전에 시작을 한 번 보낸다. 같은 동작·맥락으로 로컬 시도당 최초 결과를 한 번 보낸다. 제출을 비활성화하는 입력 검증으로 가상의 시도를 만들지 않는다. 시작 뒤 알려진 사전 저장 실패는 `blocked`, 신뢰할 수 없거나 유실된 변경 응답은 거절이 아닌 `unknown`이다. 사용자 재시도는 새 시도다. 캐시 무효화 전에 확인 결과를 보내 이후 재조회 오류로 성공한 변경을 뒤집지 않는다.

**제출 전** 확인 창 닫기는 작업 실패가 아니라 대화상자 이벤트로 측정한다. 시간 초과·숨겨진 탭·언마운트는 취소 증거가 아니다. 나중에 불확실한 결과를 확정할 수 있으면 별도 해결 이벤트를 사용하고 최초 결과를 다시 보내지 않는다. 중복 방지·대응의 한계는 [구현](implementation-and-validation.ko.md)을 따른다.

| ------------------------ | ------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |

지원 범위는 [파일 어댑터](../../../src/services/api/files.ts)가 정한다. 에피소드 삭제는 폴더를 없애고 원고 위치를 옮기는 것이며 원고 전체 삭제가 아니다. 미지원 일반 폴더 동작·에피소드 재정렬은 실제 사용자 경로에서 시도할 때만 blocked로 다루며, 없는 메뉴 노출을 만들지 않는다. 설정 분류 변경은 확인된 결과 문서 유형과 move를 사용하며 선택 컨트롤만으로 변환 성공을 추정하지 않는다.

가져오기가 내부 생성·저장·정리를 담당하므로 해당 기술 단계에 파일 동작 이벤트를 중복으로 보내지 않는다. 최신화가 만든 문서, 복원 전 자동 버전과 자동 정리는 수동 파일·버전 동작이 아니다. 기존 `manuscript_saved` 전송은 별도로 유지한다.

| `document_save_issue`        | P0   | 실제 저장 시도가 해결되지 않은 오류·충돌·잠금·만료 구간에 진입할 때. `document_type`, `issue_kind: error \| conflict \| locked \| expired`, 해당 `error_category`. 재렌더링·폴링·자동 재시도마다가 아닌 연속 문제 구간마다 한 번. 이미 잠긴 문서 열기는 저장 문제가 아니다.                                                                                                                                                                                                                  |
| `document_save_recovered`    | P0   | 그 문제 구간이 확인된 저장 또는 서버 최신본을 성공적으로 불러와 채택하는 것으로 해결됐을 때. `document_type`, `resolution: retry_saved \| keep_mine_saved \| take_theirs_loaded`, 선택적 `duration_seconds`는 문제 시작부터 잰다. 버튼 클릭·dirty 상태만으로 회복이 아니다. take_theirs는 사용자 초안 저장이 아닌 서버 내용을 불러와 채택하는 뜻이다.                                                                                                                                        |
| `document_structure_changed` | P1   | 사용자가 편집기 구조 변경을 로컬에 확정할 때. `document_type`, `action: relation_add \| relation_remove \| relation_description \| alias_change \| core_mark \| core_unmark`. 영속화가 아닌 편집 의도·상태이며 지속성은 저장 측정과 함께 본다. 중요 설정은 설정 문서에만 있다. 속성 키·관계 설명·대상 ID를 보내지 않는다.                                                                                                                                                                    |

| `document_import_result`     | P0   | 묶음 반복 처리가 끝났을 때. `outcome: success \| partial \| failed \| unknown`, `file_count`, `succeeded_count`, `failed_count`, `unknown_count`, `is_retry`, 선택적 `duration_seconds`. 시도한 파일은 정확히 한 카운터에 속한다. 생성과 본문 저장이 **모두** 성공해야 succeeded다. failed_count는 확인된 생성·본문 저장·로컬 읽기 실패를 포함하며 서버 거절만이 아니다. 성공과 비성공이 섞이면 partial, 성공 없이 불확실한 파일이 하나라도 있으면 unknown, 전부 명확한 비성공이면 failed다. |

활성 편집 시간은 제한된 근사값을 제안한다. 초안을 바꾸는 동작 뒤 다음 동작 또는 무입력 30초 중 빠른 때까지의 전경 시간을 센다. 겹치지 않는 구간을 쓰고 숨은 시간을 제외하며 구간 경과 시간을 상한으로 한다. 정확한 타이핑 시간을 꾸며내지 않고 소수 초를 유지한다. 키 입력 수·텍스트 길이는 필요 없다. 편집 없는 읽기 세션에는 요약을 보내지 않는다. 편집 뒤 저장 문제가 생겼으면 이후 저장 성공이 없어도 포함할 수 있다.

가져오기 창 닫기는 dismissed·submitted이며 롤백이 아니다. 이미 성공한 파일은 남는다. 재시도는 남은 파일만 시도하며 새 생성 없이 본문 저장을 재개할 수 있다. 로컬 기록에서 생성 거절·생성 응답 유실·본문 저장 실패·불확실한 본문 저장을 구분해야 한다. 현재 오류 타입으로 커밋을 확정할 수 없으면 unknown으로 세어 묶음에 남기며 통신 실패로 문서가 없다고 추정하지 않는다. 집계를 편하게 하려고 재시도 동작을 바꾸거나 정리를 실행하지 않는다.

TXT·Markdown의 download_handoff는 비어 있지 않은 사용 가능한 Blob URL과 실제 다운로드 헬퍼 호출을 요구한다. PDF의 print_handoff는 준비 뒤 `window.print()`를 호출했다는 뜻이다. `afterprint`는 인쇄·취소 모두에서 발생하므로 성공이나 사용자 취소를 확정하지 못한다. 미지원 DOCX·HWP와 Blob 기능 부재를 전달 성공으로 세지 않는다. 사전 저장 결과는 `DocumentSession`의 상태·dirty를 확인하며 Promise 이행만으로 판단하지 않는다.

영역·동작 조합을 명시한다. 관계도는 select_node, clear_selection, open_document, filter_kind, filter_episode, search, clear_search, zoom_button, fit을 지원한다. 타임라인은 select_chapter, open_document, filter_episode, filter_row, toggle_group, search, clear_search를 지원한다. 미지원 조합은 무시한다. 로컬 검색·지우기는 입력 중단 500ms 또는 명시적 선택 뒤 안정된 확정 값에만 발생시킨다. 같은 값을 억제하고 키 입력마다 보내지 않는다. count_bucket 생략은 모름이며 0이 아니다. 카메라 이동, 휠 프레임, hover와 애니메이션 틱은 제외한다.

기존 `project_search`는 성공 검색의 기존 시계열로 유지한다. 과정 분석에는 새 started·result 쌍을 쓰며 **결과 건수를 `project_search`와 합산하지 않는다.** 기존 의미를 조용히 바꾸지 않고 옮겨갈 수 있도록 의도적으로 병행하는 시계열이다. 관계도·타임라인·도움말 필터는 로컬 동작이며 서버 검색 요청이 아니다.

stopped는 명시적 로컬 중단 때문에 로컬 턴이 멈췄다는 뜻이다. 현재 어댑터는 취소 요청 실패를 무시하므로 서버 취소는 확인하지 못한다. 언마운트·대화 삭제로 생긴 Abort를 사용자 중단으로 분류하지 않는다. blocked에는 실제 사전 저장·사용 가능 가드가 필요하며 현재 검사하지 않는 사전 저장 불리언만으로는 만들 수 없다. failed·rejected·stopped를 분류하기 전에 오류 출처와 명시적 중단 원인을 구현에서 노출해야 한다. 그전에는 불확실한 스트림 종료를 interrupted로 다루며 서버 실패라고 주장하지 않는다.

| `feedback_submit_result`       | P1   | `outcome: success \| rejected \| blocked \| unknown`, 해당 공통 결과 필드. 어댑터가 기대하는 성공 응답을 확인해야 성공이며 창 닫기·본문 지우기가 발생 기준이 아니다.                                                                                                                                                                                                                                                                                                                                                                    |
| `action_result_resolved`       | P1   | 앞서 unknown이었던 변경 결과를 로컬에서 대응시킨 뒤 확정할 때. `operation_group: project \| file \| document \| memo \| chat_session \| account \| feedback \| setting_check_start \| setting_check_cancel`, 해당하면 그 그룹에 정의된 `action`, `outcome: success \| rejected \| accepted`, 원래 시작부터의 선택적 `duration_seconds`. unknown 시도당 한 번. accepted는 확인된 점검 시작·취소에만 쓰며 작업 종료 성공이 아니다. 불확실한 재조회에는 보내지 않고, 결과를 얻으려 무작정 재시도하거나 잃은 정확한 개수를 복원하지 않는다. |

이전 헬퍼가 알려진 실패에 기존 `auth_failed`를 추가로 보낼 수 있다. 겹치는 시계열을 합산하지 않는다. 탐색은 GA를 기다리지 않는다. 탈퇴·로그아웃 결과는 현재 시도의 담당 코드가 살아 있을 때 이동 전에 전송하되 가능한 범위의 전달로 취급하고 탈퇴 설문 내용은 넣지 않는다. 계정 탈퇴가 과거 익명 GA 관찰의 삭제를 뜻하지는 않는다.

## 제외 항목·별도 판단이 필요한 확대

키 입력별 이벤트, 선택 텍스트, 편집기 트랜잭션, 마우스 위치, hover, 애니메이션 프레임, SSE 토큰·활동 프레임, 폴링, 캐시 무효화, 일반 HTTP 요청, 내부 Kafka 이벤트를 GA에 보내는 제안은 없다. 활성화할 수 없는 비활성 컨트롤에 가상 이벤트를 보내지 않는다. 서식·찾기 바꾸기 상세, 카메라 제스처 요약, 작업공간 환경설정 영속화 지표는 보류한다. 기본 편집 요약·실제 기능 진입으로 더 넓은 사용을 먼저 다룬다.

정확한 생애 최초·동일 프로젝트 분석, 기기 간 신원, 원시 ID, 서버에서 GA로 보내기는 이 목록 밖이다. 별도의 데이터 소스와 대응 정책이 필요하다. 새 파라미터·열거 값은 적용 전 이 목록과 타입 검증기에 함께 추가한다. 서비스 페이로드의 임의 문자열이 자동으로 허용되는 일은 없다.
