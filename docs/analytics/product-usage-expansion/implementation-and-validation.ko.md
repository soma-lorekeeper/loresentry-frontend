# 구현·검증 계획

[English](implementation-and-validation.md) · [폴더 안내](README.ko.md)

상태: 예정 작업만 정리했다. [이벤트 목록](additional-events.ko.md)은 페이로드 계약, [현재 상태](current-state.ko.md)는 이미 있는 동작을 기록한다. 이번 문서 작업으로 아래 계측·GA 변경·실행 검증을 구현하거나 수행하지 않았다.

## 1. 기능 적용 전 공통 구현

기존 `src/features/analytics/`에 이벤트별 파라미터 맵, 열거 값 검사, 음이 아닌 숫자 검사를 갖춘 타입화된 전송기를 추가한다. 설치된 태그, 기존 `analyticsEnabled` 조건, URL·리퍼러 필터와 검색 URL 정제를 재사용한다. 새 사용 이벤트가 두 번째 태그를 초기화하거나 호스트·데이터 모드 제한을 완화하거나 mock 수집을 암묵적으로 켜면 안 된다.

전송기는 예외를 밖으로 던지지 않고 가능한 범위에서 전달한다. 이동·저장·인증·모델 요청을 지연시키지 않는다. 도메인 객체 전체를 전달하지 않고 미정의 키·잘못된 값을 버린다. 확인된 0은 유지하고 모르는 값은 생략한다. 등록 확인 청구 장치를 포함한 기존 이벤트명·의미를 보존한다. 과거 발생을 방금 일어난 것처럼 채워 보내지 않는다.

동작 조정 코드에서 시작 시각·진입점·제한된 맥락을 한 번 잡는다. 불투명한 시도 토큰은 메모리에만 두고 전송하지 않는다. 시도를 한 번 끝내고, unknown 결과를 별도 이벤트로 한 번 해결할 수 있게 한다. 완료 기록은 제한된 수명으로 정리하고 프로젝트 변경·언마운트에서 정리한다. 로컬 대응에 필요한 식별자만 보관하며 문서 원문을 복사하지 않는다.

기능 변경 전에 결과 담당 지점을 하나로 정한다. 유효한 사용자 의도는 핸들러, 결과는 검증된 서비스 응답·명시적 상태 전이가 담당한다. 기다리는 캐시 무효화·이동 전에 결과를 기록한다. 서비스 변경 성공 뒤 재조회 실패는 변경 거절이 아니다. 공통 API 계층이 정제된 결과 신호를 제공할 수는 있으나 요청·재시도·폴링·가져오기 내부 호출마다 무차별 GA를 보내면 안 된다.

### 관찰 제약

- **저장:** 실제 확인과 `DocumentSession`의 dirty·상태를 함께 쓴다. 저장 Promise는 실패 뒤에도 이행될 수 있다. 콜백 추가 전 실제 상태 기계를 확인하며 이벤트 때문에 오류를 saved로 바꾸지 않는다.
- **챗:** 재조회 전에 검증된 최종 턴·SSE done 신호를 보존한다. 명확한 서버 실패, 응답 유실, 사용자 중단, 언마운트·대화 삭제를 구분할 오류 출처·중단 원인을 노출한다. 현재 실패를 무시하는 취소 요청으로 서버 취소를 증명하지 못한다. 미저장 차단을 약속하기 전 기존 사전 저장 불리언 처리를 확인한다. 동작 수정은 계측의 부작용이 아닌 별도로 명시할 구현 변경이다.
- **점검:** 요약·상세 폴링 관찰을 중앙화하고 로컬 실행 ID로 중복을 막는다. 토스트·탭 표시와 무관하게 작동한다. RUNNING → DONE·FAILED·CANCELLED를 다루고 처음 읽은 과거 종료 자료에서 가상 종료를 만들지 않는다.
- **가져오기:** 묶음 카운터·파일별 생성·본문 저장 단계를 로컬에 보관한다. 이번 묶음 성공과 앞선 재시도들의 누적 성공을 구분한다. 정리는 새 수동 파일 동작이 아니다.
- **불확실한 변경:** 기존 도메인 계약으로 동일한 로컬 시도에 결과를 확실히 대응시킬 때만 해결을 보낸다. 비슷해 보이는 더 최신 상태, 다른 사람의 편집, 새 최신 실행만으로는 부족하다. 응답·조회 API로 증명할 수 없으면 unknown을 유지한다. 분석을 위해 없는 엔드포인트를 만들거나 변경 요청을 재전송하지 않는다.

## 3. 적용 묶음 제안

### P0: 핵심 가시성과 관찰 결과

1. 공통 검증기·전송기·로컬 시도·관찰 담당을 마련하고 기존 수집을 보존한다.
2. 작업공간 기능 진입·준비, 수동 파일 생성, 가져오기, 편집·저장 문제를 넣는다.
3. 필요한 명시적 오류·중단 신호를 포함해 AI 챗 열기·턴·중단·보이는 제한을 넣는다.
4. 설정 오류 점검의 시작·결과·취소 관찰, 보고서 표시·판정 영속화를 넣는다.
5. 의도한 테스트 환경에서 합성 프로젝트 내용으로 준비·챗·점검·최신화 분기를 검증한다.

목록의 모든 P0 행을 구현·검증했을 때만 P0 완료로 보고한다. 그렇지 않으면 미완료 행과 이유를 열거하고 묶음을 미완료로 유지한다. 쉬운 이벤트만 켠 뒤 묶음 전체 완료로 보고하지 않는다. 새 타입 신호·없는 렌더링 준비 계약은 의존 조건이며 결과를 추정할 권한이 아니다.

### P1: 범위와 설명 확대

관리 동작, 버전·내보내기·이미지, 검색·탐색, 메모, 챗 결과 활용·대화 관리, 최신화 검토, 계정·약관·언어, 랜딩, 도움말, 피드백, 기존 도메인이 지원하는 unknown 해결로 넓힌다. 해당 흐름의 창 열기·닫기도 추가한다. 측정 계획의 보고서를 구성하고 실제 페이로드를 확인한 뒤 기능 간 차이를 해석한다.

### P2: 선택적 상호작용 상세

기본 보고서의 유용성을 확보한 뒤 배치·패널 동작, 최초 온보딩 단계, 작업공간 둘러보기 과정을 넣는다. 컨트롤별 서식 상세, 카메라 제스처 계측, 서버 작업공간 설정 영속화 지표는 목록 밖 보류로 유지한다. 이 상세를 이미 다뤘다고 주장하지 않으면서 넓은 계획을 순차 적용할 수 있다.

## 4. GA 설정·전달 검증

아래는 완료 작업이 아닌 후속 작업이다.

1. 대상 속성의 태그·향상된 측정·맞춤 정의·주요 이벤트·내부 트래픽 필터·보고서 제공 범위를 조사한다. 수동 정제 페이지 조회와 기존 기록 기반 자동 페이지 조회 제한을 보존한다. 앱 이벤트를 정제했다고 향상된 측정 전체가 개인정보 측면에서 안전하다고 가정하지 않는다.
2. 자동 사이트 검색·폼·외부 링크 수집을 특별히 확인한다. [향상된 측정](https://support.google.com/analytics/answer/9216061?hl=en)은 검색어·폼 메타데이터·링크 자료를 수집할 수 있다. 현재 검색 URL 정제는 알려진 쿼리 키를 다루며 새 이벤트가 값을 다시 넣으면 안 된다. 인쇄 중 document.title을 원고 제목으로 잠시 바꾸는 경우를 포함해 page_title·자동 필드와 실제 전송 페이로드를 확인한다. 확인할 노출 가능성이며 실제 유출을 관찰했다는 뜻은 아니다.
3. 기존 정의·여유를 확인한 뒤 측정 계획 중 필요한 맞춤 측정기준·측정항목만 추가한다. 이전 계획 없이 기존 정의를 삭제·변경하지 않는다. 실패 결과도 포함하는 일반 result 이벤트가 자동으로 성공 주요 이벤트가 되지 않는다.
4. 먼저 제어된 로컬·모의 수집에서 검증하고 mock·localhost 트래픽은 실제 GA 속성에서 제외한다. 계측 검사는 결정적인 가짜 수신기를 쓰고 실제 API·SSE 응답은 별도 연결 검증을 한다.
5. 권한이 있는 대상 환경·계정에서 합성 내용으로 대표적인 실제 여정을 실행한다. 수집 요청을 포착하고 실시간·활성화한 DebugView로 수신·이벤트 순서·값·제외를 확인한다. 브라우저에서 HTTP가 나갔다고 GA 수신이 증명되지는 않으며 DebugView 수신도 보고서 범위·분모의 정확성을 증명하지 못한다. [Google 이벤트 안내](https://developers.google.com/analytics/devguides/collection/ga4/events)는 설정과 검사 화면을 설명한다.
6. 처리 뒤 실제 보고서의 필터·맞춤 파라미터 제공·유입 범위·날짜·시간대·결과 의미를 검증한다. 구현 작업 기록에 빌드·커밋, 환경, 호스트·데이터 모드, 사례, 정제 페이로드 예시, GA 수신과 남은 공백을 기록한다. 쿠키·실제 원고·계정 식별자를 보고서에 저장하지 않는다.

기존 활성 조건은 `loresentry.com`으로 제한돼 있어 보통의 localhost·개발 도메인 접속으로 실제 GA 전달을 증명할 수 없다. 검증 때문에 전역 제한을 완화하지 않는다. 제어된 수신기와 의도적으로 구성한 전달 검사는 근거 역할이 다르다.

## 5. 인수 사례

해당 이벤트 묶음을 구현할 때 골라 수행할 필수 검사이며 이번 작업의 PASS 결과가 아니다.

| 사례                    | 필요한 관찰                                                                                                                                                           |
| ----------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 수집 활성·비활성        | 올바른 운영·API·ID 조건에서 허용하고 mock·localhost·빈 ID·온보딩 및 둘러보기 기능 예시에서는 보내지 않는다. 둘러보기 과정 이벤트로 데모 기능 이벤트가 생기지 않는다.  |
| 페이로드 경계           | 미정의 키·열거 값, ID·이름·검색어·인용·내용·원시 URL·오류를 거른다. 확인된 0은 유지하고 모르는 개수는 생략한다. 자동 필드도 검사한다.                                 |
| 중복 담당               | Strict Mode·재렌더링·캐시 갱신·재시도 콜백·요약 및 상세 폴링이 로컬 시도·전이 하나를 중복시키지 않는다. 실제 다시 열기·재시도는 새 발생으로 센다.                     |
| 뷰 활성화·조회          | 보존된 숨은 탭은 기능 열기·준비를 보내지 않는다. 포커스 전환·명시적 재시도의 is_retry·준비 상태가 맞는다. 분할 창·복원 캐시도 확인한다.                               |
| 명확·불확실한 변경 결과 | 타입화된 거절은 rejected, 유실·신뢰 불가 응답은 unknown, 이후 캐시 실패는 확인 결과를 뒤집지 않는다. 미지원·무요청 전제조건은 시도했을 때만 blocked다.                |
| unknown 해결            | 동일 시도의 확실한 도메인 결과에 별도 해결을 최대 한 번 보낸다. 불확실한 상태·다른 사람의 동작에는 보내지 않는다. 변경을 무작정 재전송하지 않는다.                    |
| 자동 저장 구간          | 편집 없으면 요약이 없다. 숨은 시간을 빼고 60초 구간 뒤 숨김·해제가 와도 카운터가 겹치지 않는다. 기존 manuscript_saved를 조용히 재정의하지 않는다.                     |
| 저장 오류·충돌          | 오류 상태의 이행된 저장 Promise는 성공이 아니다. 반복 재시도가 같은 연속 문제를 반복 생성하지 않는다. 회복은 확인된 저장·최신본 채택을 기다린다.                      |
| 가져오기 선택·부분 묶음 | 미지원·중복 선택과 제출을 구분한다. 파일 둘의 부분 성공·본문만 재시도가 성공 + 실패 + 모름 = 시도 수를 지킨다. 닫기는 롤백이 아니다.                                  |
| 이미지 단계             | 티켓·업로드·완료 성공 뒤 연결 실패는 set_image 성공이 아니다. 연결 확인 유실은 unknown이다.                                                                           |
| 내보내기 한계           | TXT·Markdown 전달에는 유효 URL·헬퍼 호출이 필요하다. PDF 준비·인쇄 호출은 인쇄 완료가 아니며 afterprint는 취소를 구분하지 못한다. DOCX·HWP·Blob 부재는 성공이 아니다. |
| 검색 대체               | 빠른 대체·지우기는 기존 논리 시도를 superseded로 끝내고 늦은 이전 결과를 무시한다. 빈·오류·캐시·재시도를 구분하고 검색어·길이를 보내지 않는다.                        |
| 챗 종료                 | delta 뒤 연결 유실은 완료가 아니며 검증된 done 턴은 캐시 재조회 전에 완료로 센다. delta·activity별 계측은 없다.                                                       |
| 챗 중단·사전 저장       | 사용자 중단·언마운트·삭제·SSE 연결 끊김을 구분한다. 사전 저장 false를 가상의 저장 성공 또는 실제 가드 없는 blocked로 만들지 않는다.                                   |
| 챗 시간·결과 활용       | 처음 비어 있지 않은 내용을 준비를 포함한 로컬 시도부터 잰다. 복사는 클립보드 결과를 기다리고 근거 요청·대상 조회를 구분한다.                                          |
| 점검 종료 상태          | 탭 열림·닫힘과 무관하게 RUNNING→DONE·FAILED·CANCELLED를 로컬에서 한 번 관찰한다. 최초 종료 자료는 새 완료를 만들지 않고 과거 보고서 열람은 센다.                      |
| 점검 취소 경합          | 취소 확인과 이후 CANCELLED를 구분한다. DONE으로 경합하면 done으로 보고하며 취소로 강제하지 않는다.                                                                    |
| 점검 판정               | 판정을 골랐다고 확인 전 저장으로 세지 않는다. 되돌리기·이유 수정·재시도의 action이 맞고 이유·어긋남 ID를 싣지 않는다.                                                 |
| 최신화 호환             | 두 변경 없음 경로, 저장된 개수, 불확실한 반영 재조회를 유지한다. 검토 동작은 제안 수락이 아니고 실패·차단된 닫기는 closed를 만들지 않는다.                            |
| 계정 이동               | 약관·탈퇴·로그아웃은 실제 확인 지점에서 이동 전 보내되 이동을 지연시키지 않는다. 폐기 미확인은 unknown이고 동의 성공은 세션 성공이 아니다.                            |
| 언어·다시 보기          | 계정 언어 동기화 실패에도 로컬 언어는 바뀔 수 있다. 최초 온보딩·다시 보기·둘러보기를 구분하며 tutorial_complete를 중복시키지 않는다.                                  |
| 전달·보고서             | 로컬 포착, 실제 서비스 소비, GA 수신, 최종 보고서 검증을 구분해 기록한다. 비활성·차단·유실을 기능 미사용·실패의 증거로 삼지 않는다.                                   |

## 완료 근거

이번 문서 작업에서는 언어 쌍, 동일한 이름·열거 값, 상대 링크, 서식과 변경 범위를 검사한다. 이후 구현에서는 위 관찰 계약의 의미 있는 테스트와 실제 코드 변경에 필요한 프런트 검사를 수행한다. 문서·링크 검사를 GA 도달 증거로 쓰지 않고, 문서 작업을 끝내려고 운영 변경을 실행하지 않는다.
