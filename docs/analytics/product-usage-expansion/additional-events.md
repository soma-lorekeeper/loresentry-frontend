# Additional event catalog

[한국어](additional-events.ko.md) · [Folder guide](README.md)

Status: proposal only. This is the only definition of new event names in this folder. Existing events retain their [current contracts](current-state.md). P0/P1/P2 are rollout batches, not deployment status.

## Shared contract

Every new event includes `schema_version: usage_v1` and `ui_locale: ko | en`. Only the parameters named for that event, plus the applicable shared fields below, may be sent. An omitted value means unknown/not applicable; do not replace it with zero, an empty string or an inferred success.

| Field              | Allowed value or source                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| ------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `entry_point`      | One of `landing_header`, `landing_body`, `landing_footer`, `project_list`, `onboarding`, `sidebar`, `new_tab`, `file_menu`, `document_header`, `editor`, `search`, `graph`, `timeline`, `memo_panel`, `chat_launcher`, `chat_home`, `chat_conversation`, `selection_toolbar`, `check_home`, `check_report`, `check_toast`, `refresh_sidebar`, `refresh_review`, `account_menu`, `guide`, `shortcut`, `other`. Choose the actual caller; do not infer it from a later render. |
| `document_type`    | `manuscript`, `character`, `place`, `organization`, `item`, `event`, `worldview`; omit if unknown or not a document.                                                                                                                                                                                                                                                                                                                                                         |
| `entity_kind`      | `document` or `episode`. User-created general folders/sections are not an implemented API feature.                                                                                                                                                                                                                                                                                                                                                                           |
| `outcome`          | Only the subset specified for the event below. `success` means an acknowledged operation, not necessarily a newly changed row. `rejected` requires a definite refusal, `blocked` a known precondition preventing execution, and `unknown` a mutation whose result cannot be established.                                                                                                                                                                                     |
| `error_category`   | `network`, `auth`, `validation`, `conflict`, `locked`, `not_found`, `unavailable`, `limit`, `cancelled`, `other`. Include only for applicable non-success results; derive from trusted typed state, never raw text or HTTP bodies.                                                                                                                                                                                                                                           |
| `stage`            | `prepare`, `save_documents`, `request`, `stream`, `result_read`, `image_ticket`, `image_upload`, `image_complete`, `image_attach`, `draft_save`, `account_sync`, `other`. Include when the owner actually knows the stage.                                                                                                                                                                                                                                                   |
| `duration_seconds` | Finite, non-negative browser elapsed seconds from the matching local start to the observed result, excluding later cache invalidation. Use a monotonic clock. Omit if the matching start was not observed.                                                                                                                                                                                                                                                                   |
| `count_bucket`     | `0`, `1`, `2_5`, `6_20`, `21_plus`. Numeric counts specifically named below are non-negative integers.                                                                                                                                                                                                                                                                                                                                                                       |

No project, document, run, finding, chat-session, message, user or attempt identifiers are transmitted, including hashes. IDs can be used **locally** for deduplication and matching. Do not transmit content, titles, filenames, search terms, quotes, reasons, email addresses, URLs or raw error messages in custom parameters. Existing URL/referrer sanitization remains in force.

### Action lifecycle

For each `*_started` / `*_result` pair, send the start once when a valid explicit action enters its coordinator, before pre-save or the mutation request. Send one initial result per local attempt with the same action/context. Local validation that disables submission does not fabricate an attempt. A known pre-save failure after the start produces `blocked`; an untrusted/lost mutation response produces `unknown`, not rejection. A user retry creates a new attempt. Emit acknowledgment before cache invalidation so a later reload error does not reverse a successful mutation.

Closing a confirmation **before submission** is measured by dialog events, not by an operation failure. A timeout, hidden tab or unmount does not prove cancellation. If an unknown result can later be established, use the separately defined resolution event; do not emit a second initial result. See [implementation](implementation-and-validation.md) for deduplication and matching limits.

| `document_import_started`    | P0    | A valid press of Import/Retry starts one batch. `file_count`, `import_format: text \| markdown \| mixed`, `is_retry: 0 \| 1`, `entry_point`. Count only files attempted in this batch.                                                                                                                                                                                                                                                                                                                                                                         |
| `document_import_result`     | P0    | The batch loop settles. `outcome: success \| partial \| failed \| unknown`, `file_count`, `succeeded_count`, `failed_count`, `unknown_count`, `is_retry`, optional `duration_seconds`. Partial means successes plus any unsuccessful files; no success and any uncertain file means unknown; all definite unsuccessful outcomes means failed. |

Summary active time is a proposed bounded approximation: count foreground time after a draft-changing interaction until the next interaction or 30 seconds of idle, whichever is earlier. Use disjoint intervals, exclude hidden time, cap at the window elapsed time, and retain fractions rather than inventing exact typing time. No keystroke counts or text lengths are needed. Do not send a summary for an unedited read-only session. A save issue after edits can be included without a later successful save.

Import's dialog-close events indicate dismissed/submitted, never rollback: previously successful files stay imported. A retry attempts only remaining files and can resume fill without another create. Local bookkeeping must distinguish a refused create, a lost create response, failed fill and uncertain fill. If current error types cannot establish commitment, count unknown and keep it in the batch; do not infer nonexistence from network failure. Do not change import retry behavior or run cleanup merely to make analytics counts convenient.

For TXT/Markdown, download_handoff requires a nonempty usable Blob URL and actual invocation of the download helper. For PDF, print_handoff means `window.print()` was invoked after preparation. `afterprint` fires after either printing or cancellation; it cannot establish success or a user cancellation. Unsupported DOCX/HWP and missing Blob capability must not be handoff successes. Evaluate `DocumentSession` status/dirty state for pre-save results; a fulfilled Promise alone is insufficient.

For chat, first_content_seconds measures local elapsed time from chat_turn_started to the first nonempty content delta, including session creation/pre-save if present; it is not model-only latency. duration_seconds ends when the final turn or interruption is observed, before refetches. citation_count is the completed answer's validated citation-array length, not SSE-frame count. Omit unavailable values. A retry/edit is a new turn attempt, not another success for the old attempt.

stopped means an explicit local stop caused the local turn to abort; the current adapter ignores cancel-request failures, so server cancellation is unverified. Abort on unmount/session deletion must not be classified as user Stop. blocked requires a real pre-save/availability guard; the current unchecked pre-save boolean cannot supply that result. Error provenance and explicit abort cause must be exposed by the implementation before classifying failed, rejected or stopped. Until then use interrupted for uncertain stream termination, without claiming the server failed.

## Exclusions and additions requiring a separate decision

No per-keystroke, selection text, editor transaction, mouse position, hover, animation frame, SSE token/activity frame, poll, cache invalidation, generic HTTP request or internal Kafka event is proposed for GA. No new event is emitted for a disabled control that cannot be activated. Formatting/find-replace detail, camera gesture summaries and workspace-preference persistence metrics are deferred; basic editing summaries and real feature entry already cover their broader use.

Exact first-ever/same-project analysis, cross-device identity, raw IDs and backend-to-GA sending are outside this catalog. They need a separately designed data source and matching policy. A new parameter or enum value must be added to this catalog and the typed validator before rollout; arbitrary strings from service payloads never become permitted automatically.
