# 유입과 온보딩 애널리틱스 QA 결과

실행: 2026-10-31 15:00~15:16경 한국 시간. Windows ego lite에서 운영 사이트와 API를 `tools/google-test-id/account.json`의 첫 번째 계정으로 검증했다. 자격증명을 기록하지 않고 계정 참조와 실제 신원이 일치하는지 확인했다. 이 계정은 이미 온보딩을 완료한 상태였다. 프로젝트와 로그인 검증 전 인증 `e4cba81`, 게이트웨이 `28a3985`, 프런트엔드 `01e70f4`의 CI/CD가 모두 성공했다. 랜딩 페이지 확인은 프런트엔드 배포 완료 전에 수행했다.

실시간 보고서는 전체 집계이므로 다른 방문자의 이벤트가 포함될 수 있다. 매개변수는 브라우저 `dataLayer`에서 확인했으며 GA에서는 확인하지 않았다. 이 결과만으로 UTM의 최종 기여, OAuth 왕복 전체의 이벤트 순서, GA 보고서의 완전성을 증명할 수 없다.

## 추가 확인이 필요한 관찰

- 로그아웃을 확정한 뒤 화면에는 로그아웃 실패가 표시됐지만 이후 자격증명을 포함한 `/auth/users/me` 조회는 401을 반환했다. 프로젝트 목록으로 이동하자 로그인 화면이 표시됐다. 로그아웃 요청과 서버 원인은 수집하지 못했으므로 원인을 확정하지 않은 상태 불일치 관찰이다.
- 첫 로그인 시도는 OAuth 복귀 URL이 `result=success`였지만 화면에서 실패를 표시했다. 복귀 후 확인한 `dataLayer`에는 `page_view`만 있었고 기대한 실패 이벤트는 관찰하지 못했다. 두 번째 시도는 성공했다. 원인과 관찰 시점 밖의 이벤트 전송 여부는 미확인이다.

## 수행하지 않은 범위

로그인된 테스트 신원은 이미 가입과 온보딩을 마쳤다. 두 번째 테스트 신원은 로그인돼 있지 않았고 서비스 가입 상태도 확인하지 못했다. 신규 가입 상태를 만들기 위해 계정을 삭제하거나 초기화하지 않았다. 따라서 최초 등록, 약관, `sign_up`, 온보딩 선택과 완료, 예시 프로젝트 생성, 실패 분기, 가입까지의 GA 기여 연결, 가입부터 refresh까지의 퍼널은 미검증이다. 이전 refresh QA는 [refresh QA 결과](../refresh/qa-results.ko.md)에 별도 기록돼 있으며 가입부터 이어진 실행은 아니다.

합성 프로젝트는 테스트 계정에 남겨 두었다. 다른 프로젝트는 변경하지 않았다.
