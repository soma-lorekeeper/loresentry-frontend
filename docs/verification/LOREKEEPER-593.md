# LOREKEEPER-593 탭 간 인증 전환

2026-09-26 Web Locks로 일반 요청을 공유 잠금, 로그인·로그아웃을 배타 잠금에 연결했다.
전환 의도는 localStorage와 storage 이벤트로 공유한다. 진행 요청의 응답 헤더와 본문을
받은 뒤 전환하며 일반 요청끼리는 직렬화하지 않는다. 호출자가 취소해도 실제 fetch를
취소하거나 잠금을 조기 해제하지 않는다. 이전 세대의 결과는 화면에 반영하지 않는다.

OAuth 이동 중에는 비밀값 없는 전환 표식을 남겨 새 탭의 보호 요청도 차단한다.
복귀 탭의 표식과 현재 세대가 일치할 때만 계정을 확인한다. React 중복 효과에서도
동일 확인 요청을 공유한다. 로그아웃 응답 처리가 끝나기 전에 새 로그인을 시작하지 않는다.

## 검증

Playwright Chromium 153과 Firefox 155에서 실제 Web Locks·storage 이벤트·HttpOnly
Set-Cookie를 사용한 8개 테스트가 통과했다. 두 일반 요청의 동시 진행, 지연 헤더 배출 후
로그아웃, 늦은 탭 참여, 로그아웃 뒤 새 로그인, 호출자 취소와 로그인 탭 종료를 확인했다.
이 테스트는 HTTP fixture와 실제 프론트 요청 모듈을 사용한다. 실제 Auth/BFF 브라우저
통합은 Work 599에서 수행한다. 단위·컴포넌트 231개와 타입·린트 검사도 통과했다.

```bash
pnpm exec playwright install chromium firefox
pnpm exec playwright test
```

## 복구 범위

정지한 탭이 응답을 처리하지 못하면 전환은 기다린다. 타임아웃으로 강제로 잠금을 풀지
않는다. 사용자는 해당 탭을 재개하거나 종료한 뒤 진행한다. 로그인 탭이 닫히면 표식은
남으며, 다른 로그인 창을 닫았다는 사용자 확인 뒤 ‘중단된 로그인 복구’로 재시작한다.
이 복구는 조율 밖의 남은 응답을 취소한다고 보장하지 않으며 재로그인이 필요할 수 있다.
공유 저장소 또는 Web Locks를 사용할 수 없으면 보호 요청과 전환을 실패 처리한다.
다른 브라우저 프로필·기기·직접 BFF 접근은 이 탭 조율에 포함되지 않는다.
