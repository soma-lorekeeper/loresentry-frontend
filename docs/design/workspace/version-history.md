# 버전 기록

[파일 헤더](./file-header.md)의 `버전`을 선택하면 저장된 버전 목록과 현재 문서를
견주는 모달을 연다.

```text
┌──────────────────────────────────────────────────────────────────────┐
│ 레나 아르벨                                                      ×   │
├───────────────┬──────────────────────────────────────────────────────┤
│ 버전 기록      │ ┌─ 선택한 버전 ────────┐ ┌─ 현재 문서 ───────────┐  │
│               │ │ 9월 7일 15:04        │ │ 지금                  │  │
│ ▸ 오늘 15:04  │ │ ──────────────────── │ │ ───────────────────── │  │
│    수동 저장   │ │ 분류     ⊙ 캐릭터     │ │ 분류     ⊙ 캐릭터      │  │
│   오늘 09:22  │ │ 설명     항해사다…    │ │ 설명     기억을 읽는…  │  │
│    자동 저장   │ │ 관련조직 [은빛 항해단] │ │ 관련조직 [은빛 항해단] │  │
│   어제 22:19🗑│ │ 관련원고 [12화]       │ │ 관련원고 [12화][11화]  │  │
│    수동 저장   │ │ ──────────────────── │ │ ───────────────────── │  │
│   9월 3일 …   │ │ 레나는 타인의 기억이… │ │ 레나는 타인의 기억이…  │  │
│    자동 저장   │ │ 짙은 안개 속에서도…  │ │ 짙은 안개 속에서 한…   │  │
│               │ │ —                    │ │ 그래서 그는 오래된…    │  │
│               │ └──────────────────────┘ └───────────────────────┘  │
│               │                    [버전 저장]  [이 버전으로 복원]   │
└───────────────┴──────────────────────────────────────────────────────┘
```

## 모달과 배경

버전 기록은 확인 대화상자가 아니라 모달이다. 두 층은 배경 처리로 구분한다.

| 층 | 배경 | 쓰는 곳 |
| --- | --- | --- |
| 대화상자 | 불투명한 차단막, 흐림 없음 | 한 문장을 묻고 닫는 확인 |
| 모달 | 어둡게 덮고 흐리게 | 그 안에서 읽고 고르는 자리 |

- 뒤 문서를 흐리게 두는 것은 형태만 남겨 지금 보던 자리를 잃지 않게 하려는
  것이다. 완전히 가리면 어느 문서의 기록인지가 사라진다.
- 크기는 [그래프 변경 사항](../workflow/graph-refresh.md) 모달과 같다. 두 모달 모두
  좌우로 문서를 견주는 자리라 같은 크기를 쓴다.
- `Esc`, `×`, 모달 밖 선택은 모달을 닫고 파일 헤더의 `버전`으로 포커스를 돌린다.
- 모달이 열려 있는 동안 문서를 편집할 수 없다.
- 포커스를 모달 안에 가둔다.
- 모달 머리에는 **문서 이름을 크게** 둔다. `버전 기록` 같은 기능 이름을 제목
  자리에 놓지 않는다. 어느 문서의 기록인지가 먼저 읽혀야 한다.

## 버전 목록

- 목록은 모달 **왼쪽**에 둔다. 그래프 변경 사항 모달과 같은 자리다.
- 머리에 `버전 기록`을 표시한다. 무엇의 기록인지는 모달 머리의 문서 이름이
  이미 말하므로 여기서 다시 말하지 않는다.
- 각 줄에는 저장 시각과 저장 방식(`수동 저장` 또는 `자동 저장`)을 표시한다.
- 시각은 최근일수록 사람 말에 가깝게 적는다. `오늘 15:04`, `어제 22:19`,
  그보다 오래되면 `9월 3일 17:40`.
- 최신 버전이 맨 위에 오며, 모달을 열면 최신 버전을 고른 상태로 시작한다.
- 선택한 줄은 테두리 없이 바탕색으로만 구분한다.
- 위·아래 방향키로 버전을 옮기면 비교 영역이 따라 바뀐다.
- 목록 머리 `버전 기록`은 본문색으로 둔다. 왼쪽 기둥에서 유일한 제목이라
  보조색으로 두면 아래 목록에 묻힌다.
- **포인터가 올라간 줄에만 오른쪽 끝에 삭제 버튼을 드러낸다.** 쉬는 줄에는
  두지 않는다. 네 줄 모두 삭제 버튼을 달고 있으면 목록이 아니라 관리 화면이 된다.
- 포인터가 올라간 줄은 선택한 줄과 **같은 바탕색**을 쓴다. 저장소가 hover와
  선택에 같은 색을 쓰는 것을 그대로 따른다. 둘을 가르는 것은 삭제 버튼이고,
  지금 어느 버전을 보고 있는지는 오른쪽 비교 영역이 말해 준다.
- 삭제는 되돌릴 수 없으므로 확인 대화상자를 거친다.
- 선택한 버전은 삭제할 수 없다. 다른 버전을 고른 뒤 지운다.

## 비교

**두 문서를 나란히 놓는다.** 왼쪽이 선택한 버전, 오른쪽이 현재 문서다.

- **각 열은 문서를 그대로 그린다.** 속성 표가 위에 오고 그 아래에 본문이 이어지는
  순서, 속성 이름과 값의 자리, 관련 속성을 감싼 칩 박스까지
  [속성 문서 편집 영역](./structured-file-editor.md)과 같다. 비교 화면에만 있는
  표기를 새로 만들지 않는다. 읽던 그대로 보이는 것이 견주기 쉽다.
- `속성`·`본문` 같은 구획 제목을 붙이지 않는다. 문서에 없는 제목이라 두 열을
  문서가 아닌 표로 보이게 만든다. 속성 표의 테두리가 이미 두 구획을 가른다.
- 줄 번호를 붙이지 않는다. 같은 이유다.
- **각 열을 테두리 상자로 감싼다.** 두 문서를 견주는 자리라 어디까지가 한
  문서인지가 먼저 보여야 한다. 세로선 하나로 가르면 속성 표의 가로줄과 만나
  격자처럼 읽힌다.
- 상자 안쪽에는 상하좌우 여백을 둔다. **속성 표의 가로줄이 상자 테두리에
  닿으면 안 된다.** 닿는 순간 상자와 표가 한 덩어리 격자로 보여 상자가 문서를
  묶는다는 뜻을 잃는다.
- 원고에는 속성이 없으므로 속성 표 없이 본문만 나란히 놓는다. 상자와 비교
  방식은 같으므로 별도 모형을 두지 않는다.
- 달라진 자리에만 옅은 바탕을 깐다. **고친 자리와 새로 생긴 자리에 같은 색을 쓴다.**
  무엇이 어떻게 달라졌는지는 두 열을 견주면 읽히므로, 색까지 나누면 외울 것만
  늘어난다. [그래프 변경 사항](../workflow/graph-refresh.md) 모달도 같은 색을 쓴다.
- 여러 원소를 갖는 속성은 **양쪽에 공통인 원소를 한 줄에 두고, 한쪽에만 있는
  원소만 다음 줄로 빼서 그 줄에만 바탕을 깐다.** 줄 전체를 칠하면 그대로인 원소까지
  달라진 것처럼 보인다. 빠져 나온 줄에는 속성 이름을 다시 적지 않고, 원소가 없는
  쪽에는 `—`를 놓는다.
- 바탕은 글자 높이에 맞춰 얇게 깐다. 줄 높이만큼 두껍게 칠하면 표가 아니라 블록으로
  읽힌다.
- 속성 행의 구분선과 바탕 사이에 여백을 둔다. 붙여 두면 바탕이 칸을 가득 채운 것처럼
  보여, 어느 줄이 달라졌는지가 아니라 표 전체가 물든 것으로 읽힌다.
- **두 상자는 언제나 같은 크기다.** 한쪽 문서가 길다고 그쪽 상자만 늘어나면 두 열의
  줄이 어긋나 견줄 수 없다.
- 내용이 상자보다 길면 아래를 잘라 내고 **바탕색으로 사라지는 미스트**를 덮는다.
  잘린 단면으로 끝나면 화면이 깨진 것처럼 보이지만, 흐려지며 사라지면 더 있다는 뜻으로
  읽힌다. 넘긴 범위는 [좌우 분할 보기](./tabs.md)의 편집 바와 같이 드래그로 옮긴다.
- 한쪽에만 있는 줄은 반대쪽에 `—`를 놓는다. 자리를 비워 두면 두 열의 줄이 어긋나
  같은 줄끼리 견줄 수 없다. 줄 번호를 두지 않으므로 이 자리 맞춤이 유일한
  정렬 장치다.

## 행동

- `버전 저장`: 지금 상태를 새 버전으로 남긴다. 목록 맨 위에 `수동 저장`으로
  추가한다.
- `이 버전으로 복원`: 선택한 버전의 내용으로 현재 문서를 되돌린다. 속성과 본문을
  함께 되돌리며 일부만 골라 받지는 않는다.
- **복원은 지금 상태를 먼저 버전으로 남긴 뒤 수행한다.** 그래야 복원이 되돌릴 수
  없는 행동이 되지 않는다. 잘못 복원했으면 방금 남은 버전을 다시 고르면 된다.
- 복원이 끝나면 모달을 닫고 되돌아온 문서를 보여 준다.
- 강조는 `이 버전으로 복원` 하나에만 준다. `버전 저장`은 테두리 버튼으로 둔다.
- 파일이 잠겨 있으면 두 행동을 모두 실행할 수 없다. 비교는 그대로 볼 수 있다.

## 저장된 버전이 없을 때

- 견줄 것이 없으므로 목록과 비교 영역을 비우고 안내만 표시한다.
- `이 버전으로 복원`을 두지 않고 `버전 저장`만 남긴다. 이때는 `버전 저장`이
  유일한 행동이므로 강조를 옮겨 준다.

## 컴포넌트 경계

- 모달 껍데기·목록·비교·행동은 한 컴포넌트가 함께 갖는다. 셋의 폭이 서로 묶여
  있어 따로 떼면 정렬이 어긋난다.
- 목록의 한 줄만 `Version / Entry`로 따로 둔다. 선택 여부는 바탕색 하나로 갈리므로
  인스턴스에서 덮어쓴다.
- 포인터가 올라간 줄은 `Version / Entry / Hover`로 따로 둔다. 삭제 버튼이
  붙으면서 줄이 세로 배치에서 가로 배치로 바뀌므로 덮어쓰기로는 표현할 수 없다.
- 관련 속성의 칩은 속성 문서가 쓰는 `Property / Relation Chip`을 그대로 인스턴스로
  쓴다. 비교 화면 전용 칩을 새로 만들지 않는다.
- 빈 상태는 별도 상태 컴포넌트로 둔다. 비교 영역과 복원 행동이 통째로 없어
  덮어쓰기로 표현할 수 없다.

## Pencil 시각 참조

`lorekeeper.pen`의 다음 화면을 기준으로 한다.

- 버전 기록: `168 · Property Document · Version History`(`cHMFN`)
- 저장된 버전 없음: `169 · Property Document · Version History · Empty`(`hnaQv`)

`lorekeeper.lib.pen`의 다음 컴포넌트를 `lorekeeper.pen`에서 `b:` 별칭으로
참조한다.

- 버전 목록 한 줄: `y187p` / `b:y187p`
- 포인터가 올라간 줄: `bRey4` / `b:bRey4`
- 속성 문서 버전 모달: `Ec6rs` / `b:Ec6rs`
- 저장된 버전 없음: `n0yfcX` / `b:n0yfcX`

버전 저장과 복원의 상태 전이는
[파일 헤더 동작 Workflow](../workflow/file-header-actions.md)를 따른다.

## 초기 범위 제외

- 버전 이름 붙이기
- 버전 사이의 임의 두 지점 비교
- 복원 실패와 저장 실패의 개별 상태 화면
