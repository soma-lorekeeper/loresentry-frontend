# 속성 문서 편집 영역

설정, 캐릭터, 조직, 아이템, 장소와 세계관 파일은 원고와 같은 문서 편집 구조에
속성 영역을 추가한다. 유형마다 고정된 입력 양식을 제공하지 않고 사용자가
Notion처럼 필요한 속성을 추가하고 속성의 값 유형을 선택한다.

## 화면 구조

```text
탭 바
파일 헤더                         [메모] [버전] [내보내기] [잠금]
──────────────────────────────────────────────────────────
편집 툴바
──────────────────────────────────────────────────────────
파일 제목

속성
속성 이름            속성 값
속성 이름            속성 값
[+ 속성 추가]

문서 내용
```

- 파일 헤더는 [파일 헤더](./file-header.md)를 그대로 사용한다.
- 제목과 내용은 [원고 편집 영역](./manuscript-editor.md)과 같은 방식으로 직접
  편집한다.
- 속성 영역은 제목과 내용 사이에 둔다.
- 편집 툴바는 문서 내용에만 적용하고 속성 값을 편집할 때는 적용하지 않는다.
- 모든 속성 문서는 같은 화면 구조와 컴포넌트를 사용한다. 파일 유형 아이콘과
  탭·사이드바의 유형 표시만 달라진다.

## 속성 행

```text
[유형 아이콘] 속성 이름              속성 값                    […]
```

- 속성 이름과 값은 한 행에 표시하고 모두 직접 편집한다.
- 속성 유형 아이콘을 선택하면 속성 유형 메뉴를 연다.
- `더보기`는 행 오른쪽에 항상 표시하고 `이름 변경`과 `속성 삭제`를 제공한다.
- 긴 값은 행 안에서 여러 줄로 늘어나며 다른 행과 겹치지 않는다.
- 속성 순서 변경은 초기 범위에 포함하지 않는다.
- `속성 추가`를 선택하면 마지막 행 아래에 새 속성을 만들고 속성 이름에 포커스한다.

## 속성 유형

초기 속성 유형은 텍스트와 Lorekeeper 파일 참조로 제한한다.

```text
텍스트
────────
원고
설정
캐릭터
이벤트
조직
아이템
장소
세계관
```

### 텍스트

- 짧은 값과 여러 줄 값을 모두 입력할 수 있다.
- 텍스트 안에 파일 이름을 적어도 파일 관계로 만들지 않는다.

### 파일 참조

- 선택한 속성 유형과 같은 파일만 검색하고 선택한다.
- 한 속성에 파일을 여러 개 연결할 수 있으며 선택한 파일은 칩으로 표시한다.
- 현재 프로젝트에서 휴지통에 없는 파일만 선택할 수 있다.
- 칩을 선택하면 기존 탭으로 이동하거나 새 탭에서 해당 파일을 연다.
- 칩의 제거 버튼은 참조만 제거하며 원본 파일을 삭제하지 않는다.
- 파일 참조 속성은 현재 파일에서 대상 파일로 향하는 구조화된 관계로 저장하고
  [작업공간 그래프](./graph.md)에 반영한다.
- 그래프의 관계 이름에는 속성 이름을 사용한다.

## 파일 유형별 차이

속성 문서 유형 사이에는 서로 다른 고정 필드를 두지 않는다.

| 파일 유형 | 구조 차이 |
| --- | --- |
| 설정 | 없음. 설정 아이콘과 유형 이름만 표시 |
| 캐릭터 | 없음. 캐릭터 아이콘과 유형 이름만 표시 |
| 조직 | 없음. 조직 아이콘과 유형 이름만 표시 |
| 아이템 | 없음. 아이템 아이콘과 유형 이름만 표시 |
| 세계관 | 없음. 세계관 아이콘과 유형 이름만 표시 |
| 장소 | 없음. 장소 아이콘과 유형 이름만 표시 |

사용자는 같은 속성 편집 방식으로 각 파일에 필요한 구조를 직접 만든다. 예를 들어
장소 파일에서 `상위 장소`라는 장소 참조 속성을 만들거나, 설정 파일에서 `관련
원고`라는 원고 참조 속성을 만들 수 있다. 이 예시는 기본 속성을 강제하지 않는다.

캐릭터, 조직과 아이템도 같은 원칙을 따른다.

| 현재 파일 | 사용자가 만들 수 있는 속성 예시 |
| --- | --- |
| 캐릭터 | `소속 조직` 조직 참조, `등장 원고` 원고 참조, `소개` 텍스트 |
| 조직 | `구성원` 캐릭터 참조, `활동 장소` 장소 참조, `목적` 텍스트 |
| 아이템 | `소유자` 캐릭터 참조, `관련 설정` 설정 참조, `설명` 텍스트 |

위 속성은 대표 데이터 검증을 위한 예시다. 새 파일을 만들 때 자동으로 생성하거나
필수 입력으로 강제하지 않는다.

## 편집과 저장 상태

제목, 속성과 내용은 하나의 파일 변경으로 자동 저장한다.

| 상태 | 표현 |
| --- | --- |
| 기본 | 저장된 제목, 속성과 내용을 표시 |
| 신규 빈 상태 | 빈 제목과 내용, `속성 추가`만 표시하고 제목에 포커스 |
| 속성 추가 | 새 빈 행과 열린 속성 유형 메뉴를 표시 |
| 편집 | 현재 제목·속성·내용 입력에 포커스 테두기를 표시 |
| 저장 중 | 편집 영역 상단에 `저장 중…`을 표시 |
| 저장 완료 | 같은 위치에 `저장됨`을 잠시 표시한 뒤 숨김 |
| 저장 오류 | 같은 위치에 `저장하지 못했습니다`와 `다시 시도`를 표시 |

- 별도 저장 버튼은 제공하지 않는다.
- 입력이 바뀌면 짧은 지연 후 자동 저장하고 연속 입력은 마지막 변경을 기준으로
  묶어서 저장한다.
- 저장 오류가 나도 사용자의 제목, 속성과 내용은 화면에 유지한다.
- 저장 상태는 파일 헤더에 표시하지 않는다.
- 제목이 비어 있으면 입력 아래에 오류를 표시하고 마지막 유효 이름을 탭과
  사이드바에 유지한다.

## 보조 패널과의 조합

- 파일 헤더의 `메모`를 선택하면 편집 영역 오른쪽 또는 아래에
  [파일 메모 패널](./file-memo-panel.md)을 연다.
- 파일 메모 탭의 파일명은 현재 파일 제목을 사용한다.
- 탭 바의 AI 챗 버튼은 [AI 챗 보조 사이드 패널](./ai-chat-panel.md)을 작업공간
  오른쪽에 연다.
- 패널이 열려 폭이 줄면 속성 이름과 값을 세로로 쌓고 속성 유형과 더보기 버튼은
  유지한다.
- 메모 패널과 AI 챗 패널의 동시 표시는 기존 미정 항목으로 유지한다.

## 컴포넌트 경계

라이브러리에는 모든 속성 문서가 함께 쓰는 요소만 재사용 컴포넌트로 둔다.

- `Property / Row / Text`: 이름, 텍스트 값과 더보기
- `Property / Row / File Reference`: 이름, 파일 칩과 더보기
- `Property / Add`: 속성 추가 버튼
- `Property / Type Menu`: 텍스트와 파일 유형 목록
- `Property / File Chip`: 참조 파일 아이콘, 이름과 제거
- `Property Document / Save Status`: 저장 중, 저장 완료와 저장 오류

화면의 전체 배치, 실제 속성 이름과 값은 `lorekeeper.pen`에 유지한다. 모든 속성
문서 화면은 컴포넌트를 복제하지 않고 같은 라이브러리 컴포넌트를 참조한다.
