# Lorekeeper 대표 화면 시각 방향 탐색

- 상태: 대표 화면 시각 방향 선택 완료
- 기준 화면: `12 · Manuscript Editor · Memo · Work Selected`
- Pencil 프레임 ID: `BGPNV`
- 구조 고정 기준본: `16 · Visual Baseline · STRUCTURE LOCKED`
- 기준본 Pencil 프레임 ID: `r3XP5v`
- 비교 크기: 1440 × 900
- 사용자 확인: 2026-08-28, 대표 화면과 비교 범위 승인
- 시각 선호 확인: 2026-08-28, 권장 조합 그대로 승인

이 문서는 현재 C 와이어프레임의 구조를 유지한 채 Lorekeeper의 시각 방향을
실제 제품 참고자료와 사용자 선택으로 확정하기 위한 작업 기준이다. 추상적인
스타일 이름이나 AI가 임의로 만든 분위기를 기준으로 사용하지 않는다.

## 대표 화면

`12 · Manuscript Editor · Memo · Work Selected`를 대표 화면으로 사용한다. 이
화면에는 프로젝트 탐색, 문서 탭, 파일 헤더, 원고 편집 영역과 작품 메모 패널이
함께 있어 한 화면에서 다음 항목을 비교할 수 있다.

- 장시간 집필할 본문과 주변 도구 사이의 시각적 우선순위
- 좌측 탐색 영역, 중앙 편집 영역과 우측 보조 영역의 경계
- 활성 탭, 선택한 파일과 열린 메모 패널의 상태 표현
- UI 텍스트와 원고 본문 사이의 서체·크기 체계
- 탐색 영역의 압축된 밀도와 편집 영역의 여백 균형

AI 챗이 열린 상태는 이번 대표 화면에서 제외한다. 메모 패널만으로 보조 영역이
열렸을 때의 편집 폭과 영역 경계를 비교할 수 있고, AI 챗까지 동시에 포함하면
시각 방향보다 패널 동시 표시 정책이 판단에 개입하기 때문이다.

## 모든 시각안에서 유지할 요소

- 1440 × 900 화면 크기와 동일한 콘텐츠
- C 와이어프레임의 좌측 탐색과 중앙 작업 셸 구조
- 탭 바, 파일 헤더, 원고 편집 영역과 메모 패널의 순서
- 작품 메모가 선택된 상태와 메모 패널의 오른쪽 배치
- 메모 패널 헤더의 닫기·추가·배치 전환과 작품/원고 메모 전환 구조
- 현재 프로젝트, 활성 탭, 선택한 파일과 열린 패널의 상태
- 원고 본문과 주변 UI가 차지하는 구조적 영역

시각안 비교 중에는 정보 구조, 기능, 문구, 패널 위치와 상호작용을 다시 설계하지
않는다.

## 구조 고정 기준본

`16 · Visual Baseline · STRUCTURE LOCKED`는 대표 화면을 손상하지 않고 복제한
시각안 제작 기준본이다. Pencil에서 원본과 기준본을 대조한 결과 두 프레임은 각각
145개 노드로 구성되며, 루트 프레임 이름을 제외한 노드 유형·계층·레이어 이름·문구가
일치한다.

다음 항목은 이후 비교안에서 고정한다.

- 1440 × 900 프레임 크기와 좌측 탐색·중앙 원고·우측 메모의 영역 구조
- 탭 바, 파일 헤더, 원고 편집 영역과 메모 패널의 순서와 크기
- 프로젝트·파일·탭·작품 메모의 문구와 선택 상태
- 메모 패널의 오른쪽 배치와 작품 메모가 선택된 상태
- 닫기·추가·배치 전환과 작품/원고 메모 전환 컨트롤의 위치와 의미

비교안에서는 색상, 텍스트 스타일, 표면 경계와 선택 상태의 시각 표현만 바꾼다.
구조 변경이 필요하다고 판단되면 시각안 안에서 함께 수정하지 않고 별도 UX 작업으로
분리한다. Pencil 스키마에는 편집 잠금 속성이 없으므로 프레임 이름의
`STRUCTURE LOCKED` 표시와 이 문서의 고정 목록을 변경 금지 기준으로 사용한다.

### 같은 조건에서 볼 차이

- Ulysses 근거안은 원고와 주변 도구가 한 화면에 조용히 이어지는 정도를 본다.
- iA Writer 근거안은 주변 도구보다 중앙 원고가 먼저 읽히는 정도를 본다.
- Scrivener 근거안은 좌측 탐색·중앙 원고·우측 메모의 경계와 현재 상태를 찾기 쉬운지
  본다.
- 세 안 모두 기존 C의 다크 포커스 방향을 유지하며 그라디언트, 발광, 배경 이미지와
  새로운 장식 요소를 사용하지 않는다.

### 선택 결과와 사용자 피드백

사용자는 2026-08-28에 세 단일 참고안의 차이를 육안으로 판단하기 어렵다고
말했고, 앞서 승인한 참고 조합을 실제 화면으로 만든 권장안을 최종 방향으로
선택했다.

- 선택: `20 · Visual Direction · Recommended Blend · SELECTED`
- 유지: 권장안의 전체 조합과 기존 C의 정보 구조
- 변경: 별도 요청 없음
- 제거: 별도 요청 없음

이번 선택은 모든 화면의 디자인 완료를 뜻하지 않는다. 다음 Work에서는 선택한
대표 화면에서 실제 디자인 변수와 재사용 컴포넌트 규칙을 추출하고, 그 과정에서
가독성이나 상태 구분 문제가 발견될 때 근거를 남겨 세부 값을 조정한다.

## 시각안별로 변경할 요소

- 배경과 표면의 명도 단계, 텍스트 대비와 제한적인 강조색
- UI 서체와 원고 본문 서체의 조합, 크기, 굵기와 줄 간격
- 탐색과 컨트롤의 밀도, 편집 영역의 여백과 본문 폭
- 영역 경계, 선택·활성·포커스 상태의 표현 방식
- 아이콘의 크기, 선 굵기와 레이블 결합 방식
- 반복 요소의 모서리와 표면 표현

변경 요소도 이후 정리할 실제 제품 참고자료와 사용자 선호에 근거해야 한다.
그라디언트, 발광, 과도한 카드와 장식은 별도 근거 없이 추가하지 않는다.

## 동일 조건 비교 규칙

- 모든 시각안은 대표 화면 기준본을 복제해 만든다.
- 구조, 내용과 상태를 먼저 대조한 뒤 시각 속성만 변경한다.
- 각 시각안에 참고한 실제 제품과 적용한 요소를 기록한다.
- 작업 집중, 가독성, 정보 위계와 사용자 선호를 같은 기준으로 비교한다.
- 단순 저장이나 레이아웃 오류 없음은 디자인 승인으로 간주하지 않는다.

## 실제 제품 참고자료

참고자료는 3개 제품의 공식 문서와 공식 배포 이미지만 사용한다. 각 화면에서
문제를 해결하는 요소만 가져오며 제품의 전체 스타일을 복제하지 않는다.

### iA Writer

#### 1. Library·Editor·Preview가 열린 3영역 화면

- 출처: [iA Writer Quick Tour](https://ia.net/writer/how-to/quick-tour),
  [공식 화면 이미지](https://static.ia.net/2024/09/WriterAllPanesOpen.webp)
- 활용할 요소: 중앙 Editor를 가장 넓고 단순한 면으로 두고, 좌우 보조 영역은
  얇은 경계와 명도 차이로만 분리한다. 화면의 역할을 Library, Editor, Preview로
  명확히 나누면서도 각 영역을 별도 카드로 감싸지 않는다.
- 피할 요소: Preview처럼 결과 미리보기를 항상 오른쪽에 두는 구조와 밝은 표면
  대비를 그대로 사용하지 않는다. Lorekeeper의 오른쪽 영역은 현재 파일과
  연결된 메모이며 필요할 때만 열린다.
- Lorekeeper 적용 근거: 현재 C의 좌측 탐색·중앙 편집·우측 메모 구조와 가장
  직접적으로 비교할 수 있다. 중앙 원고를 넓게 유지하면서 보조 영역의 존재를
  분명히 하는 기준으로 사용한다.

#### 2. Library를 숨긴 집중 편집 화면

- 출처: [iA Writer Write With Focus](https://ia.net/writer/how-to/write-with-focus),
  [공식 화면 이미지](https://static.ia.net/2024/09/WriterStatsOn.webp)
- 활용할 요소: 본문 줄 길이를 제한하고 편집 면 안에 충분한 여백을 둔다. 단어
  수와 같은 보조 정보는 화면 하단에서 낮은 우선순위로 표시한다.
- 피할 요소: 현재 문장 외의 본문을 항상 흐리게 만드는 Focus Mode와 탐색 영역을
  기본적으로 모두 숨기는 방식은 사용하지 않는다. 장편 원고를 고치거나 앞뒤
  맥락을 확인할 때 가독성과 위치 파악을 방해할 수 있다.
- Lorekeeper 적용 근거: 원고가 화면에서 가장 먼저 읽히게 하면서도 프로젝트
  맥락과 메모를 유지해야 하므로, Editor의 본문 폭과 여백만 참고한다.

### Ulysses

#### 3. Library·Sheet List·Editor 3영역 화면

- 출처: [Ulysses 공식 미디어 자료](https://ulysses.app/press/media/),
  [Mac 공식 화면 이미지](https://ulysses.app/assets/press/screenshots/mac/Mac-1.png)
- 활용할 요소: Library와 Sheet List는 압축된 밀도로 두고 Editor로 갈수록
  시각적 여백을 늘린다. 반복되는 카드 대신 목록, 선택 행과 얇은 구분선으로
  정보 위계를 만든다.
- 피할 요소: Library와 Sheet List처럼 유사한 탐색 목록을 한 단계 더 추가하지
  않는다. Lorekeeper에는 이미 파일 트리와 열린 탭이 있으므로 중간 목록을
  추가하면 같은 이동 경로가 중복된다.
- Lorekeeper 적용 근거: 탐색 영역은 많은 정보를 다루되 원고 편집 영역과
  경쟁하지 않아야 한다. 좌측은 압축하고 중앙에는 호흡을 주는 밀도 차이의
  기준으로 사용한다.

#### 4. Editor Focus와 Dark Mode 화면

- 출처: [Ulysses 공식 미디어 자료](https://ulysses.app/press/media/),
  [Mac 공식 화면 이미지](https://ulysses.app/assets/press/screenshots/mac/Mac-2.png)
- 활용할 요소: 다크 배경에서도 본문 면을 별도 카드로 강조하지 않고, 제한된
  본문 폭과 차분한 텍스트 대비로 집중 영역을 만든다. 주변 도구의 대비는 본문보다
  낮게 유지한다.
- 피할 요소: 현재 문장만 과도하게 강조하거나 Markdown 표식을 다수의 색으로
  드러내는 표현을 기본 상태로 사용하지 않는다. 원고 전체를 읽을 때 시각적
  연속성을 해칠 수 있다.
- Lorekeeper 적용 근거: 현재 C의 다크 무채색 방향을 유지하면서 AI가 만든
  발광·그라디언트 없이도 본문 우선순위를 만드는 근거가 된다.

### Scrivener

#### 5. Binder·Editor·Inspector가 열린 기본 화면

- 출처: [Scrivener Navigate 공식 설명](https://www.literatureandlatte.com/blog/how-to-use-scriveners-navigate-menu-to-access-elements-of-your-projects),
  [공식 화면 이미지](https://www.literatureandlatte.com/wp-content/uploads/2025/04/navigate1-1.png)
- 활용할 요소: Binder, Editor와 Inspector의 기능 경계를 분명히 하고, Inspector는
  현재 문서에 연결된 보조 정보를 보여준다. 보조 패널을 닫아 Editor 폭을 되돌릴
  수 있는 구조를 참고한다.
- 피할 요소: 상단 도구막대의 많은 아이콘과 메뉴, Inspector 안의 여러 기능을
  한꺼번에 노출하는 높은 밀도는 사용하지 않는다. 핵심 행동의 발견성과 원고
  집중을 동시에 낮출 수 있다.
- Lorekeeper 적용 근거: 파일 트리·원고·작품 메모의 기능 관계가 대표 화면과 가장
  유사하다. 메모를 현재 작업에 연결하되 필요하지 않을 때 원고 영역을 회복하는
  기준으로 사용한다.

#### 6. Composition Mode 집중 화면

- 출처: [Scrivener Navigate 공식 설명](https://www.literatureandlatte.com/blog/how-to-use-scriveners-navigate-menu-to-access-elements-of-your-projects),
  [공식 화면 이미지](https://www.literatureandlatte.com/wp-content/uploads/2025/04/navigate3-scaled-1.png)
- 활용할 요소: 원고를 화면 중앙의 제한된 폭에 두고, 집필 중 필요하지 않은
  도구를 낮은 우선순위로 보내는 방식만 참고한다.
- 피할 요소: 배경 이미지와 테마 장식, 별도의 모드로 완전히 전환하면서 탐색을
  숨기는 방식은 기본 작업공간에 적용하지 않는다. Lorekeeper는 집필 중에도 파일,
  설정과 메모를 오가야 한다.
- Lorekeeper 적용 근거: 현재 통합 작업공간을 유지하면서도 중앙 원고가 시각적으로
  독립돼 보이는 정도를 판단하는 반대 사례로 사용한다.

## 참고자료에서 공통으로 채택할 원칙

- 원고 편집 영역을 가장 넓고 단순한 표면으로 유지한다.
- 좌우 보조 영역은 카드보다 명도 차이와 얇은 경계로 구분한다.
- 탐색 영역은 압축하고 본문 영역에는 충분한 여백과 제한된 줄 길이를 둔다.
- 보조 패널은 현재 문맥에 연결하고 사용자가 닫아 원고 폭을 회복할 수 있게 한다.
- 다크 화면의 집중감은 장식이 아니라 텍스트 대비와 주변 도구의 낮은 우선순위로
  만든다.

## 참고자료에서 공통으로 제외할 원칙

- 현재 문장 외의 원고를 기본적으로 흐리게 표시하는 것
- 배경 이미지, 발광, 그라디언트와 테마 장식으로 집필 분위기를 만드는 것
- 비슷한 역할의 탐색 목록을 여러 열로 중복하는 것
- 많은 도구 아이콘과 보조 기능을 기본 화면에 동시에 노출하는 것
- 패널을 열 때 원고의 사용 가능한 폭을 확인하지 않는 것

## 시각 선호 확인안

다음 권장안은 현재 C를 폐기하는 새 스타일이 아니다. 사용자가 좋다고 판단한 C의
구조와 다크 포커스 방향을 유지하면서 실제 제품에서 확인한 장점을 구체적인
시각 속성으로 바꾼 시작점이다.

| 판단 축 | 권장 시작점 | 참고 근거 | 변경 가능한 대안 |
| --- | --- | --- | --- |
| 밝기 | 완전한 검정이 아닌 약간 따뜻한 다크 무채색 | Ulysses Dark Mode와 현재 C | 밝은 편집 면 또는 더 어두운 전체 셸 |
| 대비 | 원고와 필수 레이블은 선명하게, 주변 도구는 한 단계 낮게 | iA Writer 집중 편집 화면 | 패널별 대비를 더 강하게 구분 |
| 정보 밀도 | 좌측 탐색은 압축하고 중앙 편집 영역은 넓고 여유롭게 | Ulysses 3영역 화면 | 전체를 더 압축하거나 전체에 여백 확대 |
| 서체 인상 | UI와 원고 모두 장식 없는 산세리프를 쓰되 원고 크기·줄 간격으로 위계 형성 | 현재 C의 익숙한 인상 | 원고만 세리프 또는 모노스페이스 사용 |
| 경계와 상태 | 얇은 구분선과 작은 명도 차이, 선택 행은 배경·텍스트·아이콘을 함께 변경 | iA Writer와 Ulysses | 패널 경계를 더 뚜렷하게 표현 |
| 아이콘 | 절제된 선형 아이콘을 유지하고 의미가 모호한 행동에는 짧은 레이블 결합 | 현재 C와 iA Writer의 낮은 도구 대비 | 주요 도구를 아이콘만으로 압축 |

### 권장 조합의 의도

- 전체 인상은 Ulysses의 차분한 다크 편집 화면에 가깝게 유지한다.
- 본문 폭과 주변 도구의 낮은 우선순위는 iA Writer에서 참고한다.
- 좌측 파일 탐색·중앙 원고·우측 메모의 기능 관계는 Scrivener의
  Binder·Editor·Inspector에서 참고한다.
- Scrivener의 높은 도구 밀도, iA Writer의 본문 흐림과 Ulysses의 중복 탐색 열은
  가져오지 않는다.

사용자는 권장안을 그대로 사용할지, 위 여섯 판단 축 중 바꾸고 싶은 항목만
지정한다. 선택 결과는 다음 Work의 대표 화면 시각안 제작 기준으로 사용한다.

### 확정한 선택

사용자는 2026-08-28에 권장 조합을 그대로 사용한다고 확인했다. 다음 Work에서는
아래 여섯 기준을 모든 대표 화면 시각안의 공통 출발점으로 사용한다.

- 약간 따뜻한 다크 무채색을 전체 밝기 기준으로 사용한다.
- 원고와 필수 레이블은 선명하게, 주변 도구는 한 단계 낮은 대비로 표현한다.
- 좌측 탐색은 압축하고 중앙 편집 영역에는 충분한 여백을 둔다.
- UI와 원고 모두 장식 없는 산세리프를 사용하고 크기·굵기·줄 간격으로 구분한다.
- 얇은 구분선과 작은 명도 차이를 사용하며 선택 상태는 복수 단서로 표현한다.
- 절제된 선형 아이콘을 사용하고 의미가 모호한 행동에는 짧은 레이블을 결합한다.

다음 Work의 시각안 차이는 이 공통 기준을 뒤집는 스타일 변경이 아니라, 실제 제품
근거 안에서 명도 단계, 본문 여백, 경계 강도와 상태 표현의 세부 균형을 비교하는
방식으로 만든다.
