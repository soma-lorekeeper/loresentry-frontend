# 프로젝트 목록 최종 검증

이 문서는 프로젝트 목록과 연결된 전역 진입 화면의 상태, 접근성, 레이아웃 검증
결과를 frontend 구현 기준으로 고정한다. 집계 기준은 2026-09-01의
`LOREKEEPER-402` 디자인이다.

## 검증 범위

- 프로젝트 목록과 생성·카드 관리 화면 `91`~`110`
- 프로젝트 휴지통의 복원·영구 삭제 화면 `111`~`122`
- 사용자 메뉴, 계정 설정과 로그아웃 화면 `123`~`134`
- 사용 가이드와 피드백 진입 화면 `135`~`138`

총 48개 화면은 모두 `1440 × 900` 데스크톱 프레임이다. 화면 `118`과 `130`은
라이트 모드 대표 화면이며, 나머지 상태와 같은 구조·컴포넌트를 사용하고 `mode`
변수만 전환한다.

## 상태 완결성

| 화면군 | 기본·빈·로딩 | 주요 상호작용 | 오류·확인·완료 |
| --- | --- | --- | --- |
| 프로젝트 목록 | `91`, `93`, `94` | `92` 카드 메뉴 | `95` 조회 오류 |
| 프로젝트 생성 | `96` 초기 | `98` 제출 가능, `99` 제출 중 | `97` 필수 오류, `100` 서버 오류 |
| 프로젝트 이름 변경 | `101` 현재 값, `103` 저장 가능 | `104` 저장 중 | `102` 유효성 오류, `105` 저장 오류, `106` 완료 |
| 휴지통 이동 | `107` 확인 | `108` 이동 중 | `109` 오류, `110` 완료 |
| 프로젝트 휴지통 | `111`, `112`, `113`, `118` 라이트 | `115` 복원 중, `119` 영구 삭제 확인, `120` 삭제 중 | `114`, `116`, `117`, `121`, `122` 오류·완료 |
| 계정 설정 | `123`, `124`, `130` 라이트·긴 값 | `125` 편집, `127` 저장 중 | `126` 유효성 오류, `128` 완료, `129` 저장 오류 |
| 로그아웃 | `131` 확인 | `132` 처리 중 | `133` 오류, `134` 완료·라우트 전환 |
| 가이드·피드백 | `135` 주제, `136` 본문 | `137` 외부 창 열림 | `138` 외부 창 오류 |

빈 상태와 오류 상태는 동시에 표시하지 않는다. 처리 중에는 중복 요청을 막고,
오류가 발생하면 사용자의 입력과 선택 맥락을 유지한 채 같은 위치에서 다시 시도할
수 있게 한다.

## 키보드와 포커스

| 화면군 | 진입과 이동 | 닫기·완료 후 복귀 |
| --- | --- | --- |
| 프로젝트 목록·카드 | 사이드바 뒤 본문의 새 프로젝트 카드와 프로젝트 카드를 시각 순서로 이동한다. 카드와 더보기는 각각 포커스를 받는다. | 카드 메뉴의 `Esc`와 바깥 선택은 해당 더보기 버튼으로 복귀한다. |
| 생성·이름 변경 | 제목 입력, 보조 행동, 주요 행동, 닫기 순서로 이동한다. 오류는 입력과 연결하고 처음 발견된 오류로 안내한다. | 취소·`Esc`는 생성 카드 또는 해당 카드의 더보기로 복귀한다. 완료 후에는 생성된 프로젝트나 갱신된 카드의 다음 작업 지점으로 이동한다. |
| 확인 대화상자 | 포커스를 대화상자 안에 가두고 기본 포커스를 `취소`에 둔다. | 취소·`Esc`는 확인을 연 행동으로 복귀한다. 처리 중에는 닫기와 행동을 잠근다. |
| 휴지통 | 카드, 복원, 영구 삭제 행동을 시각 순서로 이동한다. | 복원·삭제 완료 후 다음 카드, 이전 카드 또는 빈 상태의 핵심 행동으로 복귀한다. |
| 사용자 메뉴·계정 설정 | 사용자 요약에서 메뉴를 열고 메뉴 항목, 설정 입력, 저장 행동 순서로 이동한다. | 메뉴의 `Esc`와 바깥 선택은 사용자 요약으로, 설정 닫기는 메뉴를 연 지점으로 복귀한다. |
| 가이드·피드백 | 뒤로가기, 주제·본문 링크, 피드백 행동 순서로 이동한다. | 외부 창에서 돌아오면 피드백 행동으로 복귀하고, 열기 오류에서는 재시도에 포커스를 둔다. |

상태 변화와 오류 메시지는 `aria-live` 또는 동등한 알림 영역으로 한 번만 전달한다.
비활성 행동은 포커스 순서에서 제외한다. 포커스 표시는 `color-state-hover` 잉크 음영으로
하고 강조색 테두리는 쓰지 않는다 — 강조 테두리를 여러 상태가 나눠 쓰면서 서로 구분되지
않게 된 것을 정리한 결과다. 다만 잉크 음영은 주변과 대비 1.122라 외곽선만큼 또렷하지
않으므로, 키보드 탐색이 중요한 화면에서는 초점 위치를 문구나 순서로도 알 수 있게 한다.

## 비색상 상태 표현

- 현재 위치와 선택 카드는 테두리, 외곽선 또는 굵은 레이블을 색상과 함께 사용한다.
- 포인터가 올라간 자리와 선택된 자리는 **같은 잉크의 다른 세기**로 갈린다(hover 6% ·
  선택 12%). 선택된 항목에 포인터를 올려도 선택 세기가 유지되므로, 두 상태가 서로를
  지우지 않는다.
- 로딩·처리 중·성공·오류는 아이콘과 명시적인 상태 문구를 함께 표시한다.
- 입력 오류는 필드 테두리뿐 아니라 필드와 연결된 오류 문구로 설명한다.
- 위험 행동은 행동 이름, 위험 아이콘과 별도 확인 대화상자로 구분한다.
- 외부 이동은 외부 링크 아이콘과 새 창에서 열린다는 문구를 함께 사용한다.

## 레이아웃과 구조 검증

Pencil에서 표시되는 노드만 대상으로 48개 화면을 자동 순회한 결과는 다음과 같다.

| 검사 항목 | 결과 |
| --- | ---: |
| 잘림·경계 이탈 | 0 |
| 의도하지 않은 화면 크기 | 0 |
| 이름 없는 표시 노드 | 0 |
| 색상 참조가 없는 표시 텍스트 | 0 |
| 남은 placeholder | 0 |

화면 안에서 확인된 직접 색상은 대화상자 배경 차단막 `#00000088`뿐이다. 이 값은
테마 표면이나 상태색이 아니라 콘텐츠 비활성화를 나타내는 공통 오버레이 예외다.

## 범위 보정

`134 · Project List · Logout Complete` (`N5M5TM`)는 세션 종료 완료를 알리고
`/login`으로 이동하는 전환 상태만 정의한다. 로그인 폼, 소셜 로그인, 약관과
인증 동작은 이 Deliverable의 제외 범위이므로 화면에서 제거했다. frontend는 이
화면을 인증 UI의 시각 기준으로 사용하지 않는다.

변수·컴포넌트 참조 기준은 [디자인 시스템 감사](./design-system-audit.md)를,
화면별 구현 식별자와 최종 범위는 후속 frontend 인계 문서를 따른다.
