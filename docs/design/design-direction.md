# Lorekeeper 디자인 방향

- 상태: Style B 전역 변수 적용 검토 중
- 기준일: 2026-08-28
- 적용 범위: 승인된 대표 작업 화면과 후속 화면의 시각 기준
- 기준 화면: `20 · Visual Direction · Style B Variables · REVIEW` (`K4irXB`)

이 문서는 Lorekeeper 핵심 UI의 시각·상호작용 판단 기준이다. 현재 화면은
`lorekeeper.pen`의 Style B 탐색 프레임에서 확인한 공유 변수를 전역 적용해
검토한다. Style B에 없는 원고·메모 전용 변수는 이전 승인값을 유지하며, 정보
구조는 사용자가 선택한 C 와이어프레임을 보존한다. 이전 승인 기준은 커밋
`e6568d0`에 보존돼 있다.

화면의 정보와 동작은 각 `docs/design` 문서가 사실의 기준이다. 이 문서는 그
요구사항을 어떤 우선순위와 시각 원칙으로 표현할지 정한다. 구체적인 현재 변수값은
[`lorekeeper.pen`](./lorekeeper.pen)에 저장한다.

## 확정한 방향

- 현재 검토 기준은 `20 · Visual Direction · Style B Variables · REVIEW`다.
- Style B는 공유 셸 변수의 근거로 사용하고, 원고·메모 전용 값은 근거가 생길
  때까지 이전 승인값을 유지한다.
- C의 정보 구조와 메모 패널 상호작용을 유지한다.
- 좌측 프로젝트 탐색, 중앙 탭·작업 영역, 우측 AI 챗 패널의 3영역 구조를
  유지한다.
- 다크 무채색 셸, 낮은 도구 대비와 넓은 중앙 작업 영역을 기본으로 한다.
- 원고와 현재 작업이 장식, 내비게이션과 AI 기능보다 먼저 보여야 한다.
- 상세 UI는 현재 C의 절제된 표현을 다듬는 방식으로 확장한다.
- Pencil의 `Style A · Ink Library`와 `Style C · Midnight Archive`는 미채택
  탐색안이다. `Style B · Graphite Studio`는 공유 변수의 원본으로 사용하되,
  해당 탐색 프레임의 모든 직접값을 자동으로 제품 기준으로 간주하지 않는다.

## 사용자 목표

핵심 사용자는 한 프로젝트에서 원고와 설정 자료를 오가며 장시간 집필하는
사용자다. UI는 다음 작업을 우선 지원한다.

1. 프로젝트에 들어온 즉시 현재 맥락과 마지막 작업을 파악하고 집필을 재개한다.
2. 원고를 닫거나 현재 위치를 잃지 않고 파일, 설정, 플롯과 메모를 참조한다.
3. 열린 탭, 선택한 파일과 펼쳐진 트리를 구분하고 원하는 콘텐츠로 빠르게
   이동한다.
4. AI 챗과 파일 메모를 필요할 때만 열고, 닫았을 때 원고 중심의 작업 공간으로
   돌아온다.
5. 장시간 사용 중에도 본문 가독성과 현재 상태를 유지하며 실수 없이 작업한다.

이 목표는 [집필 흐름 비교](../ux-benchmark/comparison/writing-flow.md),
[통합 작업공간](./workspace/README.md), [새 탭 화면](./workspace/new-tab.md),
[탭](./workspace/tabs.md)과 [원고 편집 영역](./workspace/manuscript-editor.md)을
근거로 한다.

현재 사용자 목표는 기존 요구사항과 경쟁 서비스 벤치마크에서 도출한 작업
가설이다. 실제 사용자 관찰과 사용성 테스트에서 다른 근거가 확인되면 이 문서의
방향을 재검토한다.

## 디자인 원칙

### 1. 집필 내용이 도구보다 우선한다

- 원고 제목과 본문이 화면에서 가장 높은 시각적 우선순위를 갖는다.
- 내비게이션, 헤더와 툴바는 현재 작업을 이해하고 실행하는 데 필요한 만큼만
  강조한다.
- Lorekeeper다운 인상은 판타지 장식이 아니라 프로젝트, 원고, 설정과 관계를
  자연스럽게 다루는 정보 구조에서 만든다.

### 2. 장시간 사용을 위해 차분하게 유지한다

- 넓고 밝은 면, 강한 채도와 반복적인 강조를 기본 화면에 사용하지 않는다.
- 완전한 검정과 흰색의 직접 대비 대신 현재 C의 부드러운 다크 무채색 단계를
  유지한다.
- 그림자나 효과보다 표면 명도 차이와 얇은 경계로 영역을 구분한다.

### 3. 현재 맥락과 상태를 분명하게 보여준다

- 현재 프로젝트, 활성 탭, 선택한 트리 항목과 열린 패널을 서로 구분한다.
- 선택·활성·오류 상태는 색상만으로 전달하지 않고 아이콘, 텍스트, 경계 또는
  형태를 함께 사용한다.
- 파일 트리는 들여쓰기, 유형 아이콘, 펼침 상태와 선택 상태를 유지한다.

### 4. 기능은 필요한 시점에 드러낸다

- 기본 화면에는 집필과 이동에 필요한 기능만 노출한다.
- 낮은 우선순위 편집 기능은 폭이 좁아질 때 `더보기`로 접는다.
- AI 챗과 파일 메모는 상시 전면 기능이 아니라 사용자가 여는 보조 패널로
  취급한다.

### 5. 새 표현보다 일관된 체계를 우선한다

- 기존 변수, Lucide 아이콘과 확인된 컴포넌트를 먼저 재사용한다.
- 새 색상, 간격, 모서리 또는 글꼴은 기존 값으로 목적을 달성할 수 없을 때만
  추가한다.
- 한 화면에서만 필요한 크기와 여백은 반복이 확인되기 전까지 전역 변수로
  만들지 않는다.

### 6. 정적 화면이 아니라 실제 작업 조건으로 판단한다

- 현실적인 파일명, 긴 원고 제목, 깊은 트리와 실제 문장으로 화면을 검증한다.
- 좌우 패널이 열린 상태, 탭이 많은 상태와 좁은 작업 폭을 함께 확인한다.
- AI가 생성한 화면의 완성도는 첫인상이 아니라 실제 작업 흐름과 접근성으로
  평가한다.

## 시각 기준

Style B 원본과 이전 승인 프레임에서 확인한 다음 기준을 검토한다.

| 항목 | 기준 |
| --- | --- |
| 색상 | 캔버스 `#1A1D1F`, 기본 텍스트 `#EDF2F2`의 Graphite 다크 무채색 체계 |
| 표면 | 사이드바·내비게이션 `#111416`, 탭 바 `#15181A`, 편집 면 `#22211F` |
| 경계 | 기본·프레임 `#3A4246`의 얇은 경계 |
| 강조 | 선택 면 `#293237`, 제한적 강조 `#A9C7D0` |
| UI 글꼴 | `Geist`를 기본으로 사용 |
| 원고 글꼴 | 공유 `Geist` 서체와 기존 30px/1.25 제목, 16px/1.78 본문 |
| 아이콘 | `Lucide` 한 계열과 기본 굵기 400의 절제된 선형 아이콘 유지 |
| 간격 | 4, 8, 10, 14, 20px의 Style B 간격 체계를 우선 사용 |
| 모서리 | 컨트롤과 카드 모두 2px를 사용 |
| 밀도 | 탐색은 압축하되 작업 영역에는 호흡을 주고 본문 폭을 제한 |
| 효과 | 기본적으로 그라디언트, 광택, 발광과 강한 그림자를 사용하지 않음 |

본문 폭과 반응형 최소 폭은 화면별 적용 과정에서 검증한다. 라이트 테마와 사용하지
않는 성공·오류 상태 색상은 현재 범위에서 미리 만들지 않는다.

### 기존 변수 판정

- 전환: 공유 색상 16개, UI 서체 1개, 맥락 크기 1개, 간격 3개와 모서리 2개를
  Style B 값으로 동기화했다.
- 유지: 원고·메모 전용 색상, 원고 크기·행간, 기본·제목 크기, 작은 간격과 아이콘
  굵기를 포함한 17개는 Style B에 직접 근거가 없어 이전 값을 유지했다.
- 추가·폐기: 변수 이름을 추가하거나 폐기하지 않았다. 기존 의미 변수 연결을
  유지해 기준 커밋과 현재 검토 상태를 같은 구조로 비교할 수 있다.

## 참고 레퍼런스

레퍼런스는 복제 대상이 아니라 특정 문제를 해결하는 참고 근거로만 사용한다.

### Lorekeeper C

- 가장 우선하는 내부 레퍼런스다.
- 프로젝트 맥락 → 마지막 작업 → 새 파일 → 최근 파일 순서를 유지한다.
- 낮은 시각 자극, 넓은 중앙 영역과 다크 셸을 유지한다.
- 탐색 선택 상태는 C의 약점으로 보고 대비와 포커스 표현을 보완한다.

### Pensiv

- [문서 편집기](../ux-benchmark/pensiv/04-document-editor.md)의 다크 무채색 셸,
  제한된 본문 폭, 낮은 도구 대비를 참고한다.
- [탭과 분할 보기](../ux-benchmark/pensiv/08-tabs-and-split-view.md)의 작업 맥락
  보존 방식을 참고한다.
- 아이콘 중심 기능의 발견성 저하와 패널 증가 시 본문 폭 축소는 답습하지 않는다.

### Muvel

- [워크스페이스 편집기](../ux-benchmark/muvel/04-workspace-editor.md)의 분명한 패널
  경계와 보조 자료 접근 방식을 참고한다.
- 높은 기능 밀도, 반복되는 테두리와 사용자에게 초기 레이아웃 구성을 맡기는
  복잡성은 답습하지 않는다.

두 서비스에서 공통으로 확인된 원고 우선순위, 제한된 본문 폭, 상태의 복합 표현과
패널 경계는 [UI 비교 원칙](../ux-benchmark/comparison/ui-principles.md)을 따른다.

## 피할 표현

- 제품 근거 없이 `작가의 서재`, `밤의 아카이브` 같은 테마를 시각적으로
  연출하는 것
- 청색·보라색 그라디언트, 발광 효과와 AI를 상징하는 장식을 브랜드 표현으로
  반복하는 것
- 모든 정보와 행동을 둥근 카드 안에 넣는 것
- 표면마다 그림자, 두꺼운 테두리 또는 서로 다른 모서리 값을 사용하는 것
- UI 전체에 장식용 세리프나 여러 글꼴을 섞는 것
- 활성 상태와 선택 상태를 채도가 높은 색상 하나로만 구분하는 것
- 실제 사용자 목표와 무관하게 정보 밀도를 높이거나 빈 공간을 장식으로 채우는 것
- 화면 전체를 다시 생성해 기존 정보 구조, 동작 또는 변수 체계를 바꾸는 것
- 시각적으로 세련돼 보인다는 이유만으로 첫 AI 출력을 채택하는 것

## UI 평가 기준

새 화면이나 변경안은 다음 질문에 모두 답할 수 있어야 한다.

### 작업 우선순위

- 첫 시선이 현재 원고 또는 현재 화면의 핵심 작업으로 향하는가?
- 프로젝트 맥락과 다음 행동을 별도 설명 없이 찾을 수 있는가?
- 보조 도구가 핵심 콘텐츠와 시각적으로 경쟁하지 않는가?

### 탐색과 상태

- 활성 탭, 선택한 파일, 펼침 상태와 열린 패널을 서로 구분할 수 있는가?
- 상태가 색상 외의 단서로도 전달되는가?
- 같은 콘텐츠를 즐겨찾기와 파일에서 열어도 하나의 작업 맥락을 유지하는가?

### 장시간 사용과 가독성

- 넓은 화면에서 본문 줄 길이가 과도하게 늘어나지 않는가?
- 텍스트와 배경 대비가 충분하면서 눈에 강하게 튀지 않는가?
- 반복되는 경계, 강조색과 컨트롤이 시각적 소음을 만들지 않는가?

### 패널과 좁은 폭

- 사이드바, 파일 메모와 AI 챗이 열려도 원고가 사용 가능한 폭을 유지하는가?
- 폭이 부족할 때 낮은 우선순위 기능이 먼저 접히는가?
- 패널이 탭 바, 파일 헤더 또는 핵심 입력 영역을 덮지 않는가?

### 접근성과 조작

- 본문과 필수 레이블이 WCAG AA 대비를 만족하는가?
- 키보드 포커스와 현재 선택 상태를 확인할 수 있는가?
- 아이콘 단독 행동에 접근 가능한 이름이나 설명이 있는가?
- 잘림, 겹침과 조작하기 어려운 작은 컨트롤이 없는가?

### 체계와 제품 적합성

- 기존 변수와 컴포넌트로 표현했는가?
- 새 시각 값이 해결하는 구체적인 문제가 있는가?
- 장식을 제거해도 Lorekeeper의 프로젝트·원고·설정 관계가 드러나는가?
- 실제 콘텐츠와 핵심 상태로 검증했는가?

## AI를 사용하는 변경 절차

AI로 UI를 만들거나 수정할 때는 다음 순서를 따른다.

1. 대상 화면 문서와 이 문서에서 사용자 목표, 유지할 구조와 평가 기준을
   추출한다.
2. 검토 프레임 `K4irXB`와 현재 전역 변수를 시작점으로 사용한다.
3. 비교가 필요하면 타이포그래피, 간격, 경계, 밀도 또는 상태 표현 중 한 축만
   변경한다.
4. 각 안에 해결하려는 문제, 유지한 요소, 변경한 요소와 예상 위험을 기록한다.
5. UI 평가 기준으로 검토하고 대표 화면과 실제 콘텐츠로 검증한다.
6. 선택한 변경만 기존 화면과 변수에 반영하고 탈락한 탐색 값은 남기지 않는다.

사용자가 전문 디자인 용어로 방향을 제시할 필요는 없다. `더 편하다`, `복잡하다`,
`현재 C가 낫다`, `우리 제품 같지 않다`와 같은 반응을 이 원칙과 평가 기준에
연결해 변경 여부를 결정한다.

## 사실의 기준

충돌이 생기면 다음 순서로 판단한다.

1. 화면의 정보와 동작: 해당 `docs/design` 화면·Workflow 문서
2. 시각·상호작용 판단: 이 문서
3. 현재 구현할 변수값과 선택 구조: `lorekeeper.pen`의 변수와 검토 프레임
   `K4irXB`

탐색용 Style Tile, 경쟁 서비스 화면과 AI가 생성한 제안은 사실의 기준이 아니다.

## 변경 조건

다음 근거가 생긴 경우에만 확정한 방향을 다시 연다.

- 실제 사용자 테스트가 핵심 작업의 실패나 반복적인 혼란을 보여준다.
- 접근성 검증에서 현재 색상, 타이포그래피 또는 상태 표현의 문제가 확인된다.
- 구현 또는 반응형 제약 때문에 원고의 사용 가능한 영역을 유지할 수 없다.
- 제품 범위나 핵심 사용자 작업이 변경된다.

변경할 때는 기존 C를 즉시 폐기하지 않고, 확인된 문제를 해결하는 한 축의 대안을
같은 콘텐츠와 조건으로 비교한다.
