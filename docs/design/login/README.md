# 로그인 페이지

## 역할

사용자 인증에만 집중한다.

## Route

```text
/login
```

## 초기 범위

- Lorekeeper 로고를 표시한다.
- `Google로 계속하기`를 제공한다.
- 이용약관과 개인정보처리방침 링크를 제공한다.
- Google 버튼을 누르면 이용약관에 동의하고 개인정보처리방침을 확인한 것으로 처리한다는 안내를 표시한다.
- 인증 방식은 Google OAuth만 제공한다.
- 이메일·비밀번호 로그인은 제공하지 않는다.
- 별도 회원가입과 비밀번호 찾기는 제공하지 않는다.
- 별도의 약관 동의 화면은 제공하지 않는다.

## 정보 구조

화면은 다음 순서로 구성한다.

1. Lorekeeper 로고
2. 로그인 목적을 알리는 제목과 짧은 설명
3. `Google로 계속하기`
4. 현재 인증 상태 안내
5. 동의 안내와 이용약관·개인정보처리방침 링크

상태 안내가 필요 없을 때는 해당 영역을 비워 둔다. 영역의 위치는 유지해
상태가 바뀐 때 핵심 행동과 약관 안내가 움직이지 않게 한다.

## 화면 상태 매트릭스

| 상태 | 진입 조건 | 상태 안내 | 핵심 행동 | 성공 후 이동 | 유지 요소 |
| --- | --- | --- | --- | --- | --- |
| 기본 | `/login` 직접 방문 또는 랜딩 페이지에서 진입 | 없음 | `Google로 계속하기` | 프로젝트 목록 | 로고, 설명, 동의 안내와 정책 링크 |
| 인증 처리 중 | Google 버튼을 실행했고 OAuth 화면으로 이동하거나 결과를 처리하는 중 | `Google 로그인으로 이동 중…` | 없음 | 인증 결과에 따름 | 기본 화면의 전체 구조 |
| 인증 취소 | Google OAuth에서 사용자가 인증을 취소해 돌아옴 | `Google 로그인이 취소됐어요.` | `다시 시도` | 프로젝트 목록 | 로고, 설명, 동의 안내와 정책 링크 |
| 인증 실패 | Google OAuth 또는 결과 처리가 완료되지 않아 돌아옴 | `로그인을 완료하지 못했어요. 다시 시도해 주세요.` | `다시 시도` | 프로젝트 목록 | 로고, 설명, 동의 안내와 정책 링크 |
| 세션 만료 | 보호된 기존 작업공간에서 세션이 만료되어 진입 | `세션이 만료됐어요. 계속하려면 다시 로그인해 주세요.` | `Google로 계속하기` | 확인된 기존 작업공간, 확인할 수 없으면 프로젝트 목록 | 로고, 설명, 동의 안내와 정책 링크 |

- 취소는 실패나 계정 문제로 표현하지 않는다.
- 실패 안내는 OAuth Provider, 내부 예외와 계정 상태를 추측하거나 노출하지
  않는다.
- 세션 만료 복귀 대상은 서버가 인증 전 작업 맥락으로 확인한 서비스 내
  작업공간만 사용한다. 대상을 확인할 수 없으면 프로젝트 목록으로 이동한다.

## 상호작용 계약

- 인증 행동은 Google 버튼 하나만 제공한다. 취소·실패 상태의 `다시 시도`도
  같은 Google OAuth를 시작한다.
- Google 버튼을 실행하면 즉시 인증 처리 중 상태로 바꾸고 추가 실행을
  막는다. 버튼은 포커스 문맥을 유지하며 `aria-disabled="true"`로 상태를 전달한다.
- `Google로 계속하기`를 실행하면 이용약관에 동의하고 개인정보처리방침을
  확인한 것으로 처리한다는 안내를 버튼과 같은 영역에서 읽을 수 있게 한다.
- 이용약관·개인정보처리방침 링크는 인증과 독립적으로 열리며, 링크를 여는
  행동만으로 동의를 표시하지 않는다.
- 별도 동의 체크박스, 인증 방식 전환, 회원가입과 비밀번호 찾기 행동은 추가하지
  않는다.

## 포커스와 상태 전달

- 기본 상태의 첫 번째 조작 요소는 Google 버튼이고, 다음은 이용약관,
  개인정보처리방침 링크 순서다. 페이지 진입 시 강제로 포커스를 이동하지
  않는다.
- 인증 처리 중에는 Google 버튼의 포커스 문맥을 유지하고 진행 문구를
  `aria-live="polite"`로 알린다.
- 화면이 이미 열린 상태에서 취소·실패·세션 만료로 바뀐 경우 상태 안내
  제목으로 프로그램 포커스를 이동한다. 새 문서로 돌아온 경우에는 제목과
  상태 안내가 먼저 읽히도록 문서 순서를 유지한다.
- 취소·실패 상태의 안내는 각각 `status`와 `alert`로 전달한다. 세션 만료
  안내는 `status`로 전달한다.
- 재시도 후 같은 상태로 돌아오면 상태 안내 제목으로 포커스를 돌려
  결과를 다시 확인할 수 있게 한다.

페이지 간 이동은 [Google OAuth 인증 Workflow](../workflow/authentication.md)를 따른다.

## 사실의 기준

충돌이 있으면 다음 순서로 판단한다.

1. 로그인 화면의 정보·표시·행동은 이 문서를 따른다.
2. 인증 상태 전환과 성공 후 이동은 [Google OAuth 인증 Workflow](../workflow/authentication.md)를
   따른다.
3. 서비스 진입 경로는 [서비스 진입 Workflow](../workflow/service-entry.md)를 따른다.
4. 시각 변수와 반복 UI는 [UI 컴포넌트 라이브러리](../component-library.md),
   `lorekeeper.pen`과 `lorekeeper.lib.pen`의 현재 구조를 따른다.

## 디자인 시작 상태

`LOREKEEPER-405` 시작 시점에 Pencil에서 확인한 기준은 다음과 같다.

- `lorekeeper.pen`의 최상위 화면 130개 중 로그인·인증 화면은 없다.
- `lorekeeper.lib.pen`의 재사용 컴포넌트 103개 중 로그인·인증 전용 컴포넌트는
  없다.
- 로그인 관련 표현은 로그아웃 완료 화면의 로그인 복귀 버튼, 안내와 정책
  링크에만 존재한다.

이 상태는 로그인 화면 설계의 시작 근거이다. 후속 작업에서 화면·컴포넌트를
추가한 뒤에는 화면 레지스트리와 최종 감사 문서를 현재 상태의 기준으로 사용한다.
