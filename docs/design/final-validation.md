# Pencil 디자인 최종 검증

`docs/design/lorekeeper.pen`은 후속 UI 논의와 frontend 구현에서 사용할 핵심 화면,
승인 변수와 재사용 컴포넌트를 한 파일에 포함한다. 별도 `.lib.pen` 파일은 필요하지
않다.

## 검증 결과

- 캔버스에서 요구사항, 탐색안, 선택 방향, 상세 화면, UI 라이브러리와 검토 결과를 이름으로 구분할 수 있다.
- 핵심 화면과 라이브러리 영역에는 이름이 없거나 `Frame`, `Text`, `Icon`처럼 역할을 알 수 없는 레이어가 없다.
- 승인 변수 40개와 재사용 원본 컴포넌트 5개가 유효하며 누락된 변수나 끊어진 인스턴스 참조가 없다.
- 새 탭 두 상태와 원고 편집 다섯 상태가 공통 컴포넌트 인스턴스를 사용한다.
- 핵심 화면에는 잘림, 의도하지 않은 겹침이나 화면 경계 이탈이 없다.
- 승인 프레임 `K4irXB`의 변수 연결 전후 계산 색상·서체·간격·모서리 집계가
  동일하다.
- `15 · UI Library`와 다섯 원본 컴포넌트에 레이아웃 문제나 끊어진 참조가 없다.

## 핵심 화면 적용 기록

### 새 탭 적용 전 대조

`08 · New Tab · Default`(`dtvaQ`)와
`09 · New Tab · No Recent Files`(`TMBRe`)는 각각 135개와 121개 노드로
구성된다. 두 화면의 구조·문구 서명은 기준 커밋과 일치하며 레이아웃 문제는 없다.

- 두 화면 모두 `Sidebar Item / Default` 2개, `Tab / Document` 1개,
  `Icon Button / Default` 1개를 인스턴스로 사용한다.
- 승인 기준과 다른 공통 값은 프레임 외곽 경계, 사이드바 표면, 사용자 아바타
  표면과 Lucide 아이콘 굵기다. 이 값은 각각 `color-border-frame`,
  `color-surface-sidebar`, `color-surface-avatar`, `icon-weight-default`로
  교체한다.
- `이어서 작업하기` 버튼의 16px 가로 여백은 `space-4`로 연결한다.
- 새 탭 콘텐츠의 42px·120px 여백은 넓고 낮은 상단 배너와 제한된 콘텐츠 폭을
  만드는 화면 전용 배치값으로 유지한다. 사이드바의 18px 상단 여백도 승인
  프레임과 같은 화면 전용 값으로 유지한다.
- 기본 상태의 최근 파일 목록과 빈 상태의 다음 행동 안내는 서로 다른 상태
  콘텐츠다. 프로젝트 맥락, 생성 유형 8개, `이어서 작업하기` 행동과 기존 문구는
  변경하지 않는다.

### 새 탭 적용 결과

- 두 프레임의 외곽 경계, 사이드바·아바타 표면, 직접 배치된 Lucide 아이콘과
  `이어서 작업하기` 여백을 승인 변수에 연결했다.
- 적용 뒤 노드 수는 135개와 121개이며 구조·문구 서명은 적용 전과 같다.
- 두 화면의 8개 컴포넌트 인스턴스는 모두 유효하고 레이아웃 문제는 0건이다.
- 최근 파일이 있는 상태와 없는 상태의 콘텐츠·행동 차이를 유지했다.

### 새 탭 최종 검증

- 같은 배율의 스크린샷에서 기본 상태는 최근 파일 탐색을, 빈 상태는 새 파일
  생성과 다음 행동 안내를 중심으로 유지한다. 두 상태 모두
  `이어서 작업하기`가 상단의 단일 강조 행동이다.
- 기본 텍스트, 보조 텍스트와 강조 버튼 레이블의 대비는 각각 13.19:1,
  5.63:1, 9.88:1이다.
- 잘림, 겹침, 화면 경계 이탈과 끊어진 컴포넌트 참조는 0건이다.
- 정적 설계에 별도 호버 프레임은 추가하지 않았다. 활성 새 탭은 탭 인스턴스의
  선택 표면·텍스트·닫기 행동을 함께 사용하며, 실제 호버·포커스 동작은 frontend
  구현 검증 범위로 남긴다.

### 원고 편집기 적용 전 대조

원고 편집기 기본(`A9Wrm`), AI 챗(`iHWvC`), 작품 메모(`BGPNV`), 원고 메모
(`dm2JC`), 하단 메모(`GY3eJ`) 상태는 각각 139개, 138개, 145개, 145개,
145개 노드로 구성된다. 다섯 화면 모두 레이아웃 문제는 0건이다.

- 기본·AI 상태는 공통 컴포넌트 인스턴스 4개, 메모 세 상태는 8개를 사용하며
  모든 `ref`가 유효하다.
- 승인 기준과 다른 공통 값은 프레임 외곽 경계, 사이드바·아바타·원고 표면,
  원고 제목·본문의 색상·크기·행간과 Lucide 아이콘 굵기다. 이 값은 각각
  `color-border-frame`, `color-surface-sidebar`, `color-surface-avatar`,
  `color-surface-editor`, 원고 전용 색상·서체 변수, `icon-weight-default`로
  연결한다.
- AI 챗의 사용자·응답 문장과 메모 직접 입력의 1.55 행간은 본문 맥락용
  `line-height-context`로 연결한다. 메모 패널 표면은 `color-surface-memo`로
  연결한다.
- 작품·원고 메모 탭의 선택 차이와 우측·하단 패널 배치 선택은 기존 상태 단서다.
  문구, 콘텐츠 구조, 선택 상태와 패널 크기·배치를 변경하지 않는다.
- 사이드바의 18px 상단 여백, 원고 읽기 열의 52px·40px 세로 여백, 패널의
  고정 폭·높이와 `0`을 포함한 비대칭 여백은 화면 구조를 만드는 직접값으로
  유지한다.

### 원고 편집기 기본·AI 챗 적용 결과

- 기본·AI 화면의 외곽 경계, 사이드바·아바타·원고 표면, 제목·본문 서체와
  직접 배치된 Lucide 아이콘을 승인 변수에 연결했다.
- AI 사용자·응답 문장의 행간은 `line-height-context`에 연결했다. AI 패널의
  320px 폭, 콘텐츠, 입력 상태와 닫기 구조는 유지했다.
- 적용 뒤 노드 수는 139개와 138개이며 구조·문구 서명은 적용 전과 같다.
- 두 화면의 컴포넌트 인스턴스 8개는 모두 유효하고 레이아웃 문제는 0건이다.
- 같은 배율의 스크린샷에서 원고 제목과 본문이 AI 패널보다 먼저 읽히며,
  패널 경계와 입력 영역은 보조 작업 영역으로 분리된다.

### 원고 편집기 메모 상태 적용 결과

- 작품·원고·하단 메모 화면의 공통 셸과 원고 서체를 기본·AI 화면과 같은 승인
  변수에 연결하고, 메모 패널 표면과 입력 행간을 메모·맥락 변수에 연결했다.
- 적용 뒤 세 화면은 각각 145개 노드이며 구조·문구 서명은 적용 전과 같다.
- 세 화면의 컴포넌트 인스턴스 24개는 모두 유효하고 레이아웃 문제는 0건이다.
- 작품 메모는 `작품 메모`와 우측 배치, 원고 메모는 `원고 메모`와 우측 배치,
  하단 메모는 `작품 메모`와 하단 배치의 선택 단서를 그대로 유지한다.
- 우측 패널의 320px 폭과 하단 패널의 280px 높이를 유지했으며, 같은 배율의
  스크린샷에서 메모 패널은 원고 읽기 영역과 경계로 분리된 보조 영역으로 남는다.

### 원고 편집기 최종 검증

- 다섯 화면의 노드 수와 구조·문구 서명이 적용 전과 일치하고, 컴포넌트 인스턴스
  32개는 모두 유효하다. 잘림·겹침·화면 경계 이탈은 0건이다.
- 원고 제목과 본문의 편집 표면 대비는 각각 14.41:1, 13.87:1이다. 기본·AI·메모
  상태 모두 제목, 본문, 보조 패널 순서의 읽기 위계를 유지한다.
- 메모 패널의 기본·보조 텍스트 대비는 각각 13.88:1, 5.92:1이고, AI 패널은
  각각 14.01:1, 5.98:1이다.
- 작품 메모·원고 메모는 선택 탭의 강조선과 텍스트 색을 함께 사용하고, 우측·하단
  배치는 선택 표면과 패널 위치를 함께 사용해 상태를 구분한다.
- 다섯 화면의 직접 배치 Lucide 아이콘은 모두 `icon-weight-default`에 연결되어
  있으며, 검증 뒤 임시 `placeholder`가 남은 루트 프레임은 없다.

## 일곱 핵심 화면 통합 검증

### 시각 규칙 일관성 대조

- 일곱 화면은 모두 1440×900이며 캔버스 `#1D1C1A`, 외곽 경계 `#68635A`,
  사이드바 `#161513`, 탭 바 `#1A1917`, 사용자 아바타 `#5A554D`의 같은 계산값을
  사용한다. 각 값은 대응하는 승인 변수에 연결되어 있다.
- 원고 편집기 다섯 상태는 편집 표면 `#22211F`, 제목 30px/1.25, 본문
  16px/1.78의 같은 계산값을 사용한다. AI 패널 `#171614`와 메모 패널
  `#181715`의 차이는 보조 도구 종류를 구분하는 승인 표면 차이다.
- 일곱 화면의 직접 배치 Lucide 아이콘 계산 굵기는 모두 400이다. 승인 변수
  40개와 재사용 원본 5개가 존재하고, 화면에서 사용하는 인스턴스 40개는 모두
  유효하다.
- 화면 전용 직접값은 사이드바의 18px 상단 여백, 새 탭 콘텐츠의 42px·120px
  여백, 원고 읽기 열의 52px·40px 세로 여백, 우측 패널 320px 폭과 하단 패널
  280px 높이다. 이 값은 콘텐츠 폭과 패널 배치 상태를 유지하므로 전역 변수로
  승격하지 않는다.
- `#00000000` 직접값은 닫힌 AI 버튼과 비선택 배치 버튼의 투명 상태 재정의에만
  남아 있다. 새로운 시각 색상이나 화면 간 불일치는 아니다.
- 이번 승인 범위는 명시된 일곱 데스크톱 화면이다. 반응형·좁은 폭, 다중 탭,
  동적 호버·포커스, 라이트 테마와 미설계 성공·오류 상태는 frontend 구현 또는
  후속 디자인 검증 범위로 남긴다.

### 대비·레이아웃·컴포넌트 최종 검증

- 같은 1440×900 배율과 실제 콘텐츠로 일곱 화면을 비교했다. 기본·빈 새 탭,
  원고 기본·AI 챗, 작품·원고·하단 메모 상태의 핵심 콘텐츠와 선택·배치 차이가
  유지되며 패널이 탭 바, 파일 헤더나 입력 영역을 덮지 않는다.
- 기본·보조 텍스트의 캔버스 대비는 13.19:1, 5.63:1이고 강조 레이블은
  9.88:1이다. 원고 제목·본문, 메모 기본·보조 텍스트, AI 기본·보조 텍스트는
  각각 14.41:1·13.87:1, 13.88:1·5.92:1, 14.01:1·5.98:1이다.
- 활성 탭은 선택 표면과 문서 아이콘·제목을, 열린 AI 챗은 활성 버튼과 실제 패널을,
  메모 범위는 강조선과 텍스트를, 패널 배치는 선택 표면과 실제 위치를 함께 사용한다.
  핵심 상태는 색상 하나에만 의존하지 않는다.
- 화면의 40개 인스턴스를 원본까지 확장해 계산값을 대조했다. 사이드바 항목 14개,
  탭 7개, 아이콘 버튼 8개, AI 버튼 5개, 메모 카드 6개의 표면·경계·여백·간격과
  모서리가 원본과 일치한다. 화면 상태·콘텐츠에 따른 너비, 활성 AI 표면·경계만
  명시적 재정의다.
- 끊어진 `ref`, 잘림, 겹침, 화면 경계 이탈, 임시 `placeholder`와 이름 없는
  핵심 레이어는 모두 0건이다. 이번 최종 검사에서 추가 수정이나 미해결 결함은
  발견되지 않았다.

## 최종 비교 화면

- `08 · New Tab · Default`
- `09 · New Tab · No Recent Files`
- `10 · Manuscript Editor · Default`
- `11 · Manuscript Editor · AI Chat Open`
- `12 · Manuscript Editor · Memo · Work Selected`
- `13 · Manuscript Editor · Memo · Manuscript Selected`
- `14 · Manuscript Editor · Memo · Below Docked`
- `20 · Visual Direction · Recommended Blend · APPROVED`

`20`은 대표 작업 화면과 시각 방향의 승인 기준이다. 변수 동기화로 공유 토큰을 쓰는
기존 화면의 계산값은 함께 갱신될 수 있지만, 다른 화면의 개별 배치·상태·접근성을
승인하거나 전체 화면 전파를 완료한 것으로 간주하지 않는다.
