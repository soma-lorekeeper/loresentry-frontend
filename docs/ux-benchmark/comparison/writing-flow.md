# 집필 흐름 비교

## 공통 작업 관계

두 서비스는 PC 화면에서 다음 세 가지 정보 관계를 유지한다.

```text
작품 구조 탐색
      ↓
원고 중심 작업 ─── 선택한 문장·설정·플롯의 맥락 정보
      ↓
진척·저장·작업 상태
```

원고를 닫지 않고 설정과 플롯을 참조한다는 점은 같다. 보조 정보를 구성하는 방식이 다르다.

- 펜시브는 파일과 탭을 패널에 열어 작업 맥락을 확장한다.
- 뮤블은 독립 문서 패널과 사용자가 선택한 위젯을 함께 배치한다.

## 시작부터 집필까지

### 펜시브

```text
로그인
→ 전체 프로젝트
→ 빈 프로젝트 또는 예제
→ 구조 템플릿
→ 프로젝트 홈
→ 문서 생성
→ 원고 작성
```

구조를 먼저 정리하는 데 강하지만 첫 원고까지 이해하고 선택할 단계가 많다.

### 뮤블

```text
랜딩
→ 통합 로그인
→ 소설 프로젝트
→ 에피소드 생성
→ 일반 편집기
→ 필요할 때 위키·메모·워크스페이스 추가
```

에피소드라는 익숙한 단위로 빠르게 시작하고 고급 기능을 나중에 노출한다.

## 항목별 비교

| 기준 | 펜시브 | 뮤블 |
| --- | --- | --- |
| 기본 철학 | 구조와 연결 관계 관리 | 집필 과정과 작업 환경 최적화 |
| 시작 방식 | 프로젝트와 템플릿 | 소설과 에피소드 |
| 콘텐츠 분류 | 문서·시트·플롯·캔버스·노트 | 에피소드·위키·캔버스·메모 |
| 열린 작업 | 상단 탭과 분할 패널 | 워크스페이스의 창과 탭 |
| 보조 정보 | 다른 파일을 패널에 열기 | 위젯과 문서 패널 |
| 빠른 실행 | 명령·검색과 단축키 | 맥락 메뉴와 위젯 |
| 구조 이해 | 관계 그래프와 파일 연결 | 위키와 캔버스 |
| 초기 난이도 | 비교적 높음 | 기본은 낮고 고급은 높음 |
