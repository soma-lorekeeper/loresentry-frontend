# 펜시브 문서 편집기

## 페이지 목적과 흐름

- 목적: 장면, 에피소드와 초고를 작성하고 관련 자료를 참조한다.
- 진입: 프로젝트 홈, 파일 트리, 검색 또는 열린 탭.
- 다음 이동: 다른 문서·시트, 댓글, 참조 패널 또는 플롯 화면.

## 화면 계층

```text
탭 바
→ 파일 헤더
→ 편집 툴바
→ 원고 작업 영역
```

| 영역 | UI 구성 | UX 역할 |
| --- | --- | --- |
| 탭 바 | 현재 열린 파일 | 동시에 생각 중인 작업 집합을 유지한다. |
| 파일 헤더 | 경로, 상태, 태그, 연결 정보 | 문서 맥락과 메타데이터를 확인한다. |
| 편집 툴바 | 문자 수, 글꼴, 크기와 줄 간격 | 원고와 직접 관련된 기능만 빠르게 실행한다. |
| 중앙 편집기 | 제한된 본문 폭과 넓은 여백 | 넓은 PC 화면에서도 장문 가독성을 유지한다. |
| 우측 패널 | 댓글 또는 보조 문서 | 원고를 닫지 않고 관련 맥락을 확인한다. |

## 시각 표현

- 짙은 무채색 배경 위에 원고를 가장 높은 시각적 우선순위로 둔다.
- 완전한 흰색보다 부드러운 밝은 회색 본문을 사용한다.
- 제목은 크기와 굵기로 구분하고 본문은 비교적 긴 줄 간격을 사용한다.
- 메뉴와 툴바의 크기와 대비를 낮춰 콘텐츠보다 덜 두드러지게 한다.
- 선택, 상태와 태그에만 제한적으로 색을 사용한다.

## 장점과 마찰

| 장점 | 마찰 가능성 |
| --- | --- |
| 원고가 항상 첫 시선을 받는다. | 어두운 화면을 선호하지 않는 사용자도 있다. |
| 관련 설정을 열어도 문서를 유지한다. | 좌우 패널이 열리면 본문 폭이 좁아진다. |
| 편집 기능의 시각적 존재감이 낮다. | 아이콘 중심 기능은 발견하기 어렵다. |
| 패널 계층이 다른 파일에도 일관된다. | 헤더와 툴바가 반복되어 세로 공간을 소비한다. |
