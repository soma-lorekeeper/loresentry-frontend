# 세션 로그인과 작업 복구

실제 API 모드는 BFF의 HttpOnly 세션 쿠키로 로그인한다. 세션 ID를 JavaScript에서
읽거나 저장하지 않는다. 기본 mock 모드는 개발 화면 확인용이며 실제 인증과 구분한다.
API 모드의 auth·account·Content 포트는 실제 BFF를 사용한다.

## 활동과 오류

서버는 마지막 인증 활동 후 14일에 세션을 만료하며 보호 API 성공 인증마다 연장한다.
로그인 유지를 위한 heartbeat나 세션 폴링은 없다. 입력만 하거나 화면만 열어 두는
시간은 인증 활동이 아니다. 문서 자동 저장 등 실제 보호 API 요청은 활동에 해당한다.
브라우저는 자체 14일 타이머로 로그인 상태를 확정하지 않는다.

SESSION_REQUIRED·SESSION_INVALID는 보호 요청을 멈춘다. 열린 작업은 유지하며 새 탭에서
로그인한 뒤 계정을 확인한다. 다른 계정이면 기존 작업의 저장을 허용하지 않는다.
SESSION_UNAVAILABLE와 통신 오류는 일시 장애로 표시하고 자동 로그아웃으로 단정하지 않는다.
저장·수정 요청을 일괄 재전송하지 않는다.

## 미저장 초안

문서 초안은 메모리에 유지하고 사용자·문서별 sessionStorage에 복구 사본을 저장한다.
사본에는 기존 서버 revision과 기준 내용도 포함하여 재로그인 뒤 충돌 검사를 유지한다.
사본 복구 후에는 자동 저장하지 않고 사용자가 다시 저장해야 한다. 응답 유실 후 동일한
내용을 다시 저장하면 이전 X-Save-Id를 재사용한다. 서버 저장을 확인하면 사본을 정리한다.

인증 안내에서 미저장 내용을 JSON으로 내려받을 수 있다. 저장소 제한으로 복구 사본을
기록하지 못하더라도 메모리 초안과 페이지 종료 경고를 유지한다. 브라우저가 강제 종료되면
메모리 내용은 보장할 수 없으며 다른 탭·기기의 초안을 자동 복원하지 않는다.

## 탭과 전환

일반 요청은 공유 Web Lock으로 병렬 처리하고 인증 전환은 배타 잠금으로 진행한다.
실제 응답 처리가 끝나기 전에 fetch 취소로 잠금을 풀지 않는다. 새 탭은 저장된 전환
상태를 확인한다. 멈춘 탭은 재개하거나 닫아야 하며 중단된 로그인은 명시적 복구로
다시 시작한다. 세부 검증과 조율 한계는 [593 기록](verification/LOREKEEPER-593.md)을 따른다.

로그아웃은 session_revocation의 confirmed·not_requested·rejected·unconfirmed를
구분한다. 서버 폐기 미확인이나 네트워크 오류를 성공으로 표시하지 않는다.
